# 診察の記録

## 概要

診察の前に医師へ聞きたいことと、診察で医師から聞いたこと（薬や指示の変更など）を、
1 回の診察ごとに端末へ残せる。次の診察の予定も、同じ 1 件として先に書いておける。
病院・診療科・医師を受診先として記録しておき、診察ごとに選び、受診先ごとに見返せる。

## 外部仕様(what)

- 下端のナビゲーションの「診察」から、題名「診察一覧」の一覧を開ける（ナビゲーションと
  診察 1 件のページは「診察」）。一覧は今日（FEAT0001 の区切り時刻に従う）以後の診察を
  近い順に、過去の診察を新しい順に並べる。見出しは持たず、両方があるときだけ境目に線を
  引く。予定日を過ぎた予定は過去の側へ移る
- 一覧の行は日付と抜き出しの 1 行を出す。抜き出しは、今日以後の診察では診察前に聞くこと
  を、過去の診察では診察で聞いたことを先に出し、どちらも空なら「まだ書いていません」と
  出す。抜き出しは日付と同じ本文の大きさで出す。行は日付と抜き出しを 1 つの節として
  読み上げる。行には受診先を出さない
- 一覧の先頭の「診察を足す」から、日付を選んで足せる。同じ日に何件でも足せる。選んだ日に
  診察があれば、別の診察を足すか、今ある診察を開くか（2 件以上なら一覧から選ぶか）を
  尋ねる
- 日付を選ぶダイアログは見出し「診察の日を選ぶ」を出し、アプリの今日に印を付ける。
  2000-01-01 から今日の 1 年後までを選べる。文字は OS の倍率 2.0 で止める
- 1 件の診察のページに、診察前に聞くことと診察で聞いたことの 2 つの欄がある。保存の
  規則と失敗の知らせは、FEAT0001 のメモと同じである
- 診察のページで日付を選び直せる。確かめを経て消せ、消すと診察の一覧へ戻る
- 受診先の画面は、診察の一覧のヘッダーのアイコンと、受診先を選ぶダイアログの「受診先を
  編集」から開ける。受診先は病院・診療科・医師名の 3 つの名前を持ち、どれか 1 つで
  足りる。表示名は「／」で区切る。足す・直す（行を押すか ⋮）・使わない・使う・いつもの
  受診先にする／外すができる。受診先は消さない。使わないにしても知らせは出さず、移した
  ことを読み上げだけで告げる（「〜を使っていない受診先へ移しました」「〜を使っている
  受診先へ戻しました」）。使わない受診先は選ぶ一覧から外れ、選んでいた診察には使って
  いない旨を添えて名前が残る
- 診察のページの見出しの帯の下・2 つの欄の上に「受診先」の行があり、押すと選ぶ
  ダイアログが開く。選ぶとすぐ保存する。「選ばない」も選べる。「キャンセル」で選ばずに
  閉じられる
- 診察の一覧の先頭に「受診先で絞り込む」の欄があり、今日以後と過去の両方を絞り込む。
  欄の名前に、表示している数と全部の数を添える（「受診先で絞り込む 2/4件」。読み上げは
  「4件中2件を表示」と言葉で読む）。選択肢の先頭の「すべて」で戻せる。一覧で選ぶまでは、
  いつもの受診先で絞り込む（無ければすべて）。選んだ絞り込みはアプリが動いている間保つ。
  絞り込んで足した診察は、その受診先を選んで作る
- どの記録にも当たらない診察を開くと、見つからない旨と、診察の一覧へ移るボタンを示す
- 体調のページの「この日全体をふり返って」の行の右端から、表示している日の診察を足し、
  または開ける。足す前に、その日付の診察を新しく作るかを尋ね、いつもの受診先を選んで
  作る。その日に診察があれば開き、2 件以上なら診察の一覧を「すべて」で開く（いつもの
  受診先を読めないときは、選ぶ前の絞り込みへ戻す）
- このボタンで開く・足す診察のページは診察の行き先で開き、戻ると（消したときも）診察の
  一覧へ出る。体調のページは押した日を保ち、ナビゲーションの「体調」で戻れる。診察の
  行き先で開いていた別の診察のページは置き換わる。開く・足す診察が一覧で選んだ絞り込みに
  隠れるときは、絞り込みをその診察の受診先（無ければ「すべて」）へ改める
- 読み込み・足す・日付の変更・削除に失敗したら、その旨を示す。一覧とページは読み込みの
  失敗と「読み込み直す」を示す

## 内部設計(how)

- ビジネスロジック層: 診察（id・日付・診察前に聞くこと・診察で聞いたこと・受診先の
  id）と、今日で今日以後と過去に分ける規則（同じ日は id で並びを決める）。受診先（id・
  名前・使うか）と受診先の名前（3 つのうち 1 つ以上）、絞り込み（すべてか 1 つの受診先）と
  その選択肢の規則
- アプリケーションロジック層
    - ポート `VisitRepository` が、診察の読み書きと stream での見張りを持つ。期間の中の
      診察日（日でまとめる）と、ある日より前の最も新しい診察日も出す。経過（TASK0006）が
      これを読む
    - ポート `CareProviderRepository` が受診先の読み書きと、いつもの受診先の読み書きを
      持つ。いつもの受診先は読み出しの側だけで守り、指す受診先が無い・使っていない・
      名前が無い・値が id でないときは無しにする。一覧で選んだ絞り込みは provider が
      アプリの動いている間持つ
    - 一覧は stream で記録を見続け、アプリが動いている間は保つ。診察のページでの変更が、
      戻る経路によらず届く
    - 欄の保存は FEAT0001 のメモと同じ部品と規則を使う。書いた後に読み直す型も共有する
    - 診察は毎日の記録の機能に依存しない。日付・今日・メモの規則・日付の見出しは
      `lib/domain` と `lib/ui` から共有する
    - 体調のページのボタンは診察の機能の部品である。診察のページへは、どこからも `go` で
      移る（体調のボタン・一覧の行・「診察を足す」・同じ日の問い合わせ）。足すときは
      共有の `addVisitAndOpen` を使う。どれも診察の行き先の一覧の上に開くので、戻り先は
      一覧である
- 永続化: 表 `visits` と `care_providers`（スキーマ版 3）
    - 診察の日付は暦の日付の文字列で、一意の制約を持たず、形は表の検査（`GLOB`）で守る
    - `visits.care_provider_id` は受診先を参照し、NULL 可である
    - 受診先の各名前は NULL か空白でない文字で、どれか 1 つを持つ
    - いつもの受診先は app_settings の `usual_care_provider` で、外部キーを持たない論理
      参照である
    - 表と関係は `docs/references/database-schema.md`（ER 図）にあり、テストが書き出しと
      照らす

## 自動化できないテスト項目

- 移行の上書き
    - 目的: 前のスキーマ版の DB を持つ端末へ上書きで入れて、記録が残るか
    - 期待結果: 起動で読み込みの失敗が出ず、入れる前と同じ記録が出て、診察を足せる
    - 観察方法: 入れる前に記録を読み取り、上書きで入れて起動し、同じ日を読み取って比べる
- TalkBack での記録
    - 目的: 一覧と診察のページを読み上げで操作できるか
    - 期待結果: 行・欄の名前と補足・各確かめのダイアログが読まれる。受診先の画面・選ぶ
      ダイアログ・一覧の絞り込みの欄・診察のページの受診先の行が読まれ、操作できる
    - 観察方法: TalkBack を有効にし、一覧から診察を開き、受診先を選び、欄へ書いて消す。
      受診先の画面で足す・直す・使わない・使うを試す
- 最大の文字サイズでの表示
    - 目的: OS の文字サイズを最大にしても、はみ出しと重なりが無いか
    - 期待結果: 一覧・絞り込みの欄・日付を選ぶダイアログ・診察のページ・受診先の画面・
      受診先の 3 つの欄のダイアログ・選ぶダイアログ・各確かめのダイアログがはみ出さず、
      重ならない
    - 観察方法: OS の文字サイズを最大にし、各画面を開いて見る

## 制約・既知の課題

- 同じ受診先で同じ日に 2 件以上の診察があり、どちらの欄も空のとき、一覧の行で見分け
  られない（TASK0015 の残課題）
- iOS は記録の領域が既定でバックアップに載り、受診先の名前も載る。扱いは Mac で作業する
  ときに確かめる（TASK0015 の残課題）
- iOS の実機・実フォントでの見え方と VoiceOver は確かめていない（Mac が無い）
- 起動時に DB を開けないとき、全画面に共通の失敗の出し方が無い（TASK0014 の残課題）
- 一覧の抜き出しは、端末を人に見せたときに読まれうる（TASK0014 の残課題）
