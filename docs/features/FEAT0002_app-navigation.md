# 画面の行き来

## 概要

体調（毎日の記録）・経過・診察の間を、画面の下端から片手で行き来できる。中身を作る作業が
まだの画面（経過）は、何の画面かと準備中であることを示す。

## 外部仕様(what)

- 体調・経過・診察の先頭の画面の下端にナビゲーションがあり、押すとその行き先が開く。
  並びは診察・体調・経過で、起動すると体調の行き先の今日の記録が開く
- 名前は常に出す。選んでいる行き先は、アイコンの後ろの塗りの形と、読み上げの「選択中」で
  示し、色だけで示さない。読み上げでは名前と何番目の行き先かを伝える
- 名前の文字は OS の文字の大きさによらず同じ大きさである。長押しで出るツールチップは、
  OS の文字の大きさのまま名前を示す
- ナビゲーションは、アプリを開いたとき（背景からの復帰を含む）と画面を移ったときに出る。
  送れる長さが残る画面を先頭から下へ送ると畳まれ、先頭へ戻すか、指で先頭の方へ少し
  戻すと出る。スクリーンリーダーを使っている間は畳まない。キーボードが出ている間は
  出さない
- 診察のページにもナビゲーションを出し、選ばれる行き先は「診察」である（体調のボタン
  から開いても同じ。FEAT0003）。ほかの下の画面（気を付けることの編集・設定・受診先）
  には出さない
- 選ばれている行き先を下の画面で押すと、その行き先の最初の画面へ戻る。行き先を替えて
  戻ると、離れたときの画面（診察のページなど）とスクロールの位置が残る
- 経過・診察の先頭の画面で戻る操作をすると、体調の記録へ戻る。体調の先頭の画面では、
  アプリを閉じる
- どのダイアログも、背景を読み上げに出さず、中に閉じるボタン（「キャンセル」、知らせは
  「閉じる」）を持つ。見える人は背景を押しても閉じられる。初めて開いたダイアログは題
  から読まれる
- 経過は、題名と、何の画面かと準備中であることを示す 1 文を示す。準備中の画面は記録や
  診察の値に見える数値や日付を出さない。診察の行き先は診察の一覧で（FEAT0003）、診察の
  ページへ移れ、戻る操作で一覧へ戻れる

## 内部設計(how)

- ビジネスロジック層: 持たない
- アプリケーションロジック層
    - 行き先は 1 つの列挙に持つ。ルーティングの枝とナビゲーションの項目はそこから網羅の
      形で作る
    - ルーティングは行き先ごとに画面の積み重ねを持つ。どの画面にも当たらない指定は
      今日のページへ戻す。行き先の識別子 `Destination.record` は名前の文言を「体調」へ
      替えた後も変えていない
    - ルーティングが位置から、下端のナビゲーションを出す画面かを決め、FEAT0001 の外枠へ
      渡す。出すのは、場所が行き先の最初の画面か、最も深く一致した経路が診察のページの
      経路のときである（`router.dart` の `_showsDestinations`）。外枠がナビゲーションを
      出し入れする。ナビゲーションはシステムのナビゲーションの余白を自分の下に持つ。
      ナビゲーションの無い画面と、畳んでいる間・打っている間は、外枠がその余白を空ける
    - 訪れた行き先の画面は、隠れている間もレイアウトを保つ。外枠はそれらのスクロールで
      ナビゲーションを出し入れしない
    - ダイアログは共有の開き方（`lib/ui/app_dialog.dart`）で開き、背景を読み上げから
      外す。Material の日付のダイアログも、この開き方で開く。2 つは `material_ui` 1.5.0 の
      組み立てを写しており、版を上げるときは読み比べる（CONTRIBUTING「依存の版」）。
      テストは、ダイアログを開く箇所を表と照らし、開く名前と route を許可した一覧に限る
    - アプリの根（`MaterialApp.router` の `builder`）に、読み上げだけで告げる欄
      （`lib/ui/spoken_status.dart`）を置く。読み上げの順で最後に来るよう画面の右下の角に
      置き、告げた文言は 5 秒後に消す（他のユーザー補助のアプリが読め、VoiceOver が
      届きうるため）

## 自動化できないテスト項目

- TalkBack での行き来
    - 目的: 画面を見ずに行き先を替えられるか
    - 期待結果: 各行き先の名前・何番目か・選択中かが伝わり、押すとその画面の題名を読む
    - 観察方法: TalkBack を有効にし、体調のページから下端のナビゲーションへ移り、
      経過・診察・体調の順に開く
- 最大の文字サイズでの行き来
    - 目的: OS の文字サイズを最大にしても、記録の欄が狭まらず、行き先を押せるか
    - 期待結果: ナビゲーションの名前がはみ出さず、送った後の記録の欄が下端まで届く
    - 観察方法: OS の設定で文字サイズと表示サイズを最大にし、今日のページを送り、
      少し戻して行き先を替える
- 戻る操作
    - 目的: 体調以外の行き先からの戻る操作で、アプリが閉じないか
    - 期待結果: 経過・診察の先頭から戻ると体調の記録が開き、体調の記録から戻ると
      アプリが閉じる
    - 観察方法: 戻るジェスチャーと 3 ボタンのナビゲーションの両方で試す。ジェスチャーは
      OS のナビゲーションバーをスワイプの形に切り替えてから試す

## 制約・既知の課題

- 経過の画面は中身が無い。TASK0006 で作る
- iOS の VoiceOver・AX5 の実フォント・端からのスワイプでの戻る操作は確かめていない
  （Mac が無い）。VoiceOver の二本指の Z でダイアログが閉じるかと、読み上げだけの欄の
  文言に 5 秒の間スワイプで届くかも同じである（TASK0015 の残課題）
- 行の ⋮ のメニュー（受診先・気を付けること）は背景を「閉じる」と読み、開き直すと閉じる
  前の項目から読まれる（TASK0022）
- ナビゲーションがシステムのナビゲーションの余白を自分の下に持つ形は、余白を渡す端末
  （ジェスチャーのナビゲーションの Android・iOS）の実機で確かめていない。自動テストは
  余白 48 dp を与えて確かめている（TASK0023）
