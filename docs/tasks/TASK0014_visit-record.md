# 診察を記録する

## 目的

診察の前に聞きたいことを書き留め、診察の後に医師から聞いたことを残せるようにする。前回の
診察からの経過を、診察日を起点に振り返り、伝えられるようにする。

## 目標

- 1 回の診察を 1 件として、診察日・診察前に聞くこと・診察で聞いたことを記録できる
  （SREQ0013）
- 次の診察の予定日を記録できる（SREQ0013）
- 診察の一覧と、1 件の診察のページを、TASK0013 が組んだ診察の行き先に置く（SREQ0013）
- 診察日を、TASK0006 の推移が読める形でポートから出す
- 今日のページから、表示している日の診察を足し、または開ける（SREQ0013）（裁定
  2026-10-05）

## 非目標

- 診察の記録から、医療上の判断・助言・受診の勧めをしない（憲章の非目標）
- 医師から聞いたことを、気を付けることや薬の一覧へ自動で取り込まない
- 予定日の通知をしない
- 診察の予定・受けた・取りやめを状態として持たない。予定かどうかは日付で読む（裁定
  2026-10-05）
- 診察に病院・診療科・医師の欄を持たない。受診先として別に記録して診察で選ぶ形は
  TASK0015_care-providers が持つ（裁定 2026-10-05）
- 診察の画面の地の色を宣言しない。毎日の記録の画面の役割で描く（裁定 2026-10-05）
- 経過の画面（TASK0006）を変えない

## 問題

- 診察の記録には表が要る。DB のスキーマは版 2 になり、このアプリで初めての移行になる
  （`CONTRIBUTING.md` の make-migrations の手順）。drift は移行の段を transaction の外で
  走らせ、全段が通った後に版を書く。版を下げたビルドは新しい版の DB を開けない
- 表の形は配布の後には移行でしか変えられない（`hazard: on-release`）
- 診察の行き先・診察のページのルート・見本の行は TASK0013 が作る（`depends-on`）。本作業は
  見本の行を実際の診察の行に置き換える。見本の行を開く自動テスト（`openSampleVisit` を
  使う外枠・行き来・ヘッダー・押せる大きさのテスト）は、記録した診察を開く形に移す
- 診察のページの位置は診察の id を持つ。TASK0013 は id を符号化して位置へ入れるだけで、
  どの id を受けても見本の画面を出す。本作業で id を記録から引くときは、どの記録にも
  当たらない id を画面へ出さない（その id のまま空の診察を見せない）（TASK0013 の第三者
  視点レビュー）
- TASK0006 の推移は診察日を軸にし、本作業を先に行う（TASK0006 の裁定記録「作業の
  分け方」）。TASK0006 が使う読み出しは、期間の中の診察日と、今日を含まない最も新しい
  診察日の 2 つである（TASK0006 の問題）
- 本作業は、前回の診察日を記録する要求が無いことと、医師に聞きたいことのメモを
  どの画面で入力するかを受け持つ
- 診察の記録を受け持つ提供要求が要求一覧に無い。知覚ゲートを通り（新しい画面）、
  既存の提供要求は診察の記録の入力を覆わないので、新規性ゲートも通る。
  spec-derive の段で採番する
- 診察の画面の地の色は、見え方記述の「覆わない範囲」にある
- 日付を選ぶ部品（`showDatePicker`）は、本アプリで初めて使う。色はテーマで明示しておらず、
  Material の既定で描かれる（見え方記述の「覆わない範囲」の部品の項）
- 2 つの欄の保存は、今日のページのメモと同じ規則にする。メモの部品は名前と補足を毎日の
  記録の文言に固定していたので、名前と補足を受け取る部品（`NoteField`）へ移す
- 日付・今日・メモの規則は毎日の記録の機能の中にあった。診察がそこへ依存すると、機能
  どうしが UI の層で互いに依存する

## 概要設計

### 構成

```
lib/
  data/          database.dart へ診察の表を足し、版を 2 にする。移行を段ごとに書く
  domain/        日付（CalendarDay）・メモの規則（note.dart）。機能が共有する
  ui/            欄（NoteField）・今日（today.dart）・日付の見出し（day_heading.dart）・
                 書いてから読み直す型（after_reload.dart）。機能が共有する
  features/
    daily_log/
      ui/        今日のページのメモは NoteField を使う。日の部品に診察のボタンを置く
    visits/
      domain/    診察（Visit）・ポート（VisitRepository）
      data/      drift 実装
      ui/        診察の一覧・診察のページ・今日のページのボタン・足して開く流れ
                 （add_visit.dart）・状態（Riverpod）
  app/           composition.dart でポートを DB へつなぐ
  l10n/          ARB へ文言を足し、見本と準備中の文を外す
drift_schemas/   版 2 の書き出し
test/drift/      移行のテストと版 2 の検査用のコード（make-migrations が作る）
```

- 診察の記録は、記録（FEAT0001）とも行き来（FEAT0002）とも別の新しい機能にする。番号は
  導出（spec-derive）のときに採る。TASK0006 も新しい機能を作るので、同じ番号を採らない
  ように導出の時点の最大値から採る
- 依存の向きは TASK0002 と同じく `ui` → `domain` ← `data`。診察は毎日の記録の機能に
  依存しない。日付・今日・メモの規則は `lib/domain` と `lib/ui` から共有する
  （`layering_test` が確かめる）。今日のページは診察のボタンを使うので、毎日の記録の UI
  から診察の UI への向きだけがある
- 診察の一覧と診察のページは、TASK0013 の `VisitsPage`・`VisitPage` の中身を差し替える。
  ルート・位置の作り方（`VisitPage.location`）・行き先は変えない

### ドメイン

- **診察**（`Visit`）: id（数）・日付（`CalendarDay`）・診察前に聞くこと（`toAsk`）・
  診察で聞いたこと（`heard`）（どちらも空なら無し）
- **予定かどうか**: 日付が今日以後なら「これからの診察」、今日より前なら「受けた診察」。
  状態は持たず、日付と今日から決める（`isPlannedOn`）。予定日を過ぎた予定は、受けた診察
  として残る。取りやめた予定は本人が消すか日付を直す
- **区分と並び**（`Visit.splitOn`）: これからの診察は近い日を先に、受けた診察は新しい日を
  先に並べる。同じ日の中は作った順（id の順）にする
- 同じ日の診察は何件でもよい。診察日の読み出しは日でまとめる

### ポート

```dart
abstract interface class VisitRepository {
  Stream<List<Visit>> watchVisits();                 // 日付、作った順。変わるたびに出す
  Future<Visit?> visitOf(int id);                    // 無ければ null
  Future<int> addVisit(CalendarDay day);             // 作った診察の id
  Future<void> setDay(int id, CalendarDay day);
  Future<void> setToAsk(int id, String? text);       // 空白だけなら消す
  Future<void> setHeard(int id, String? text);
  Future<void> deleteVisit(int id);
  Future<List<CalendarDay>> visitDaysBetween(CalendarDay first, CalendarDay last);
  Future<CalendarDay?> lastVisitDayBefore(CalendarDay day);
}
```

- 名前は「診察前に聞くこと」を `toAsk`、「診察で聞いたこと」を `heard` とする。SQL の
  キーワード（`BEFORE`・`AFTER`）を列の名前に使わない
- 消えた診察への遅れた書き込み（`setDay`・`setToAsk`・`setHeard`）は何もしない。消した
  診察が蘇らない
- `visitDaysBetween` は `day BETWEEN first AND last` を `DISTINCT` で引く。`day` は
  `YYYY-MM-DD` の文字列で、文字列の比較が日付の順に一致する（TASK0006 と同じ根拠）
- `lastVisitDayBefore` は `day < ?` の最大値を引く

### 表と移行

```
visits
  id         INTEGER PRIMARY KEY AUTOINCREMENT
  day        TEXT NOT NULL CHECK (day GLOB '[0-9]...-[0-9][0-9]')   isDay
  to_ask     TEXT NULL
  heard      TEXT NULL
  updated_at INTEGER NOT NULL   いまは読まない（daily_logs と同じ）
```

- 日付に一意の制約を付けない。後から付けると既存の重複で移行が失敗し、外すには表を
  作り直す。付けない側が後から変えやすい
- 索引は付けない。件数は年に数十件の見込みで、全件を読んでも小さい
- 版 2 の移行は `stepByStep`（make-migrations が作る段の型）の `from1To2` で表を作る。
  `beforeOpen` の `PRAGMA foreign_keys = ON` は変えない
- 手順: `schemaVersion` を 2 にする → `dart run drift_dev make-migrations` →
  生成した移行のテストを、版 1 の行が残ることを確かめる形に埋める

```

├──────────────────────────────────────┤
│           （＋ 診察を足す）            │
├──────────────────────────────────────┤

├──────────────────────────────────────┤
│ 受けた診察                            │
│ 10/5 月   薬を 1 日 2 回に減らす…   ›  │ 診察で聞いたことを先に
│ 9/21 月   まだ書いていません       ›  │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│ ←  10月19日（月）  ✎                  │ ✎ で日付を選び直す
├──────────────────────────────────────┤
│ ┌診察前に聞くこと──────────────┐    │
│ │                              │    │
│ └──────────────────────────────┘    │
│   診察の前に、医師に聞きたいことを…   │ 補足
│ ┌診察で聞いたこと──────────────┐    │
```

- 行の抜き出しは、これからの診察は診察前に聞くことを、受けた診察は診察で聞いたことを
  先に出し、無ければもう一方を出す。受けた後に見返すのは聞いたことである。区分は見出し
  （見出しの段 2）で示し、読み上げでは行ごとに区分の語を足す
- 「診察を足す」は一覧の先頭に置く。最も多い操作で、件数が増えても位置が動かない。日付は
  `showDatePicker` で選び、範囲は 2000-01-01〜今日の 1 年後とする
- 欄は毎日の記録のメモの部品を、名前と補足を受け取る部品（`NoteField`）へ移したものを
  使う。保存の規則（打つのが止まって 600 ms・欄を離れる・アプリが背へ回る・ページを

### FEAT0003

外部仕様(what):
- 下端のナビゲーションの「診察」から、診察の一覧を開ける。一覧は「これからの診察」と
  「受けた診察」に分かれる。日付が今日以後なら前者に入る。行の抜き出しは、これからの
  診察は診察前に聞くことを、受けた診察は診察で聞いたことを先に出す
- 一覧の先頭の「診察を足す」から、日付を選んで足せる。同じ日に何件でも足せる。選んだ日に
  診察があれば、別の診察を足すか今ある診察を開くか（2 件以上なら一覧から選ぶか）を尋ねる
- 1 件の診察に、診察前に聞くことと診察で聞いたことを書ける。日付を選び直せ、確かめを
  経て消せる。消すと開いた画面へ戻る
- どの記録にも当たらない診察を開くと、見つからない旨を示す
- 今日のページの「この日全体をふり返って」の行から、表示している日の診察を足し、または
  開ける。足す前に尋ねる。その日に診察があれば開き（2 件以上なら診察の一覧）、戻るとその
  日へ戻る

内部設計(how):
- 表 `visits`（スキーマ版 2）。日付に一意の制約を持たない
- ポート `VisitRepository` が、期間の中の診察日（日でまとめる）と、ある日より前の最も
  新しい診察日を出す。経過（TASK0006）がこれを読む
- 欄の保存は今日のページのメモと同じ部品と規則を使う
- 一覧はポートが出す stream で記録を見続け、アプリが動いている間は保つ。診察のページでの
  変更が戻る経路によらず届く
- 診察は毎日の記録の機能に依存しない。日付・今日・メモの規則・日付の見出しは
  `lib/domain` と `lib/ui` から共有する
- 日付を選ぶダイアログは、今日の印をアプリの今日に合わせ、文字を 2.0 倍で止める
- 今日のページのボタンは診察の機能の部品で、診察のページを記録の行き先の上へ重ねて開く。
  診察の一覧は行き先を切り替えて開く

自動化できないテスト項目:
- 版 1 の DB を持つ端末へ上書きで入れ、記録が残り診察を足せること
- 一覧と診察のページを TalkBack で操作できること
- 最大の文字サイズで、日付を選ぶ部品を含めはみ出さないこと
