# アプリの画面の行き来を組む

## 目的

体調・経過・診察を、アプリの主題として対等に行き来できるようにする。各画面の中身を
作る作業が、決まった行き先と遷移の上に積めるようにする。

## 目標

- 最上位の行き先を体調・経過・診察の 3 つにし、下端のナビゲーションで切り替える
- 下端のナビゲーションを、画面の先頭を離れたら畳み、先頭の方へ戻すと出す
- ナビゲーションの名前の文字の大きさを OS の設定によらず固定し、最大の文字でも下端の
  ナビゲーションと記録の欄が並ぶようにする（裁定記録「下端の帯の文字の固定」。当初は
  2.0 倍の頭打ちだった）
- 経過・診察と、診察の下の画面（診察のページ）を、中身の無い画面で遷移の骨格として
  実装する
- 下端のナビゲーションの色と大きさを、見え方記述に宣言する（見え方層）

## 非目標

- 経過・診察の中身（記録の読み出し・表示・入力）を作らない。中身はそれぞれ TASK0006・
  TASK0014 が持つ
- DB の表を変えない（スキーマ版 1 のまま）
- 起動時に開く画面を変えない。今日の記録のままにする
- 経過・診察の画面の地の色を決めない。R1 を広げず、毎日の記録の画面の役割で描く
- 設定の入口（今日のページのアプリのヘッダーの歯車）を変えない
- deep link を持たない（TASK0002 の規則のまま）

## 問題

- 最大の文字では縦の余白が足りない。iOS の AX5・360 x 640 dp で、今日のページの記録の欄は
  起動直後に 2 dp、アプリのヘッダーが流れた後に 58 dp である（TASK0002 の作業記録
  2026-10-02。テストのフォントの値）。下端に部品を常に出す形は成り立たない
    - 推論: 今日のページの本体（日付の帯と記録の欄）の縦は、AX5 で日付の帯 + 58 dp
      ほどしかない。起動直後に 80 dp のナビゲーションが加わると、本体が日付の帯より短く
      なり、はみ出しうる
- Material の `NavigationBar`（material_ui 1.5.0）は高さが 80 dp で固定され、文字の大きさ
  で変わらない。ラベルは `labelMedium`（12 sp）で、文字の大きさは 1.3 倍で頭打ちになる
  （`_kMaxLabelTextScaleFactor`）。見え方記述の R3（文字の大きさを OS の設定に任せる）と
  R9（操作の名前は本文の大きい段以上）に掛かる
    - TASK0030 で R9 を改め、部品の文字は Material の既定の段で示すことにした。行き先の
      名前を本文の段で固定する値は、既定と撮って見比べた上で残した（見え方記述 V96）
- 下端のナビゲーションを畳むと、画面の縦がナビゲーションの分だけ伸びる。伸びて中身が
  すべて収まると、スクロールが先頭へ戻り、畳んだナビゲーションがすぐに出てしまう
- 外枠（`AppFrame`）はキーボードの上へ持ち上がる。ナビゲーションをキーボードの上に
  残すと、メモの欄の縦が狭まる
- 畳んだ間は、行き先を替えるのに画面の先頭へ戻す操作が要る（実機の確かめの後、指で少し
  戻すと出す形にした。裁定記録「少し戻すと出す」）
- 今のルーティングは `ShellRoute` の下に今日のページを 1 つ持ち、その子に気を付ける
  ことの編集と設定を持つ。行き先ごとの画面の積み重ねを保つには `StatefulShellRoute`
  （go_router 18.0.2 が持つ）へ移す
- Android の戻る操作は、行き先の先頭の画面ではアプリを閉じる。今日の記録以外の行き先から
  戻ると、アプリが閉じてしまう
- 見え方記述は、タブとナビゲーションの部品の色を「覆わない範囲」に置いている
- 下位の画面は、中身の無い間は入口が無い。遷移を手で確かめるには入口が要る

## 概要設計

### 行き先の構成

```
体調（起動時）  /                       今日のページ（◀▶ で過去の日）
                 /avoidances             気を付けることの編集
                 /settings               設定（ヘッダーの歯車から）
経過            /review                 中身の無い画面（TASK0006 が中身を作る）
診察            /visits                 診察の一覧（TASK0014）
                 /visits/care-providers  受診先（TASK0015）
                 /visits/:visitId        診察のページ（TASK0014）
```

- 診察は、1 回の診察を 1 件とし、診察日・予定日・前に聞きたいこと・後に聞いたことを持つ
  （裁定記録「診察の記録の中身」）。診察のページは、その 1 件の画面である
- 経過は診察と分ける。経過は本人が体調の変化に気づくため（BREQ0002）、診察は医師へ
  伝えるため（BREQ0004）で、読み手が違う
- 設定はヘッダーの歯車のまま体調の下に置く

### ルーティング

```
StatefulShellRoute.indexedStack
  builder: AppFrame(location, navigation: 行き先の索引と切り替え, child: navigationShell)
  branch 診察:     /visits    → /visits/care-providers, /visits/:visitId
  branch 体調:     /          → /avoidances, /settings
  branch 経過:     /review
```

- 外枠は今までどおりすべての画面を包み、最上位の Navigator の下に置く。ダイアログは外枠
  ごと覆う
- 行き先を替えるのは `goBranch`。行き先ごとに画面の積み重ねとスクロールの位置を保つ。
  選ばれている行き先を下の画面で押すと、その行き先の先頭の画面へ戻る
- 戻る操作は、経過・診察の先頭の画面でだけ横取りして、体調の行き先へ移す
- ナビゲーションの並びは診察・体調・経過で、起動時に開く体調を真ん中に置く（裁定記録
  「行き先の名前と並び」。名前は TASK0015 で「今日」から「体調」へ替えた）

### 下端のナビゲーション

- `NavigationBar` を外枠の下端に置く。出すのは行き先の先頭の 3 画面（`/`・`/review`・
  `/visits`）と診察のページ（TASK0014）で、ルーティングが位置から決めて外枠へ渡す
- ラベルは常に出す（`alwaysShow`）。選んでいる行き先は、塗りの形（indicator）とラベルと
  読み上げの選択中で示す
- 出し入れは外枠の `_shown` が持ち、ナビゲーションを `AnimatedSize` で畳む。隠して返す
  高さは、ナビゲーションの高さから OS のナビゲーションの帯の分を引いた値にする
- 畳んだナビゲーションは、画面を先頭の方へ 24 dp 戻すと出す（揺れで出さず、先頭より
  ずっと手前で出る長さ）。数えるのは、利用者が戻す向きに送った分（指で送った分と、
  続く慣性の分）だけで、アプリが送った分と、下へ送った後に端を越えて跳ね返る分は
  数えない。向きが変わると数え直す
- 出たナビゲーションは、下へ 24 dp 送ると畳む。出た直後の指の揺れで畳まないためである。
  先頭から送り始めたときも同じ長さで畳む
- `NavigationBar` は自分の `SafeArea` で四辺の余白を取る。状態の帯は画面のヘッダーが
  受け持つので、上の余白を外して渡す。OS のナビゲーションの帯の余白はナビゲーションが
  自分の下に持ち、ナビゲーションの無い画面と、畳んでいる間・打っている間は外枠が空ける
  （TASK0023）
- キーボードが出ている間は、ナビゲーションを外す
- ラベルは本文の段（`bodyMedium`、14 sp）にし、`MediaQuery.withNoTextScaling` で
  OS の文字の大きさによらず固定する。R3 と R9 の例外として見え方記述に書く（裁定記録
  「下端の帯の文字の固定」）
- 固定はバーの下の木すべてに及び、長押しで出るツールチップの文字も固定される（ツール
  チップは自分の位置の設定を引き継ぐ）。ツールチップは固定の前の OS の倍率を読み、
  文字の大きさへ掛けて渡す
- 行き先は 1 つの列挙（`Destination`）に持つ。ルーティングの branch とナビゲーションの
  項目はそこから網羅の形で作るので、行き先を足して片方を忘れるとコンパイルが通らない
- ナビゲーションの高さが変わる各フレームで、訪れた行き先の画面がすべてレイアウトし直される
  （隠れた行き先も `Offstage` の下でレイアウトされる）。中身の無い今は小さいが、中身を
  作る作業は、画面の重さがこの回数だけ掛かることを前提にする（測っていない）

### 中身の無い画面

- 経過の画面はアプリのヘッダー（題名）と、何の画面かと準備中であることを示す 1 文を
  持つ。中身の設計は TASK0006 が持つので、文はそれを先取りしない。文は ARB から引く
- 診察の画面の中身は TASK0014 が作った。本作業が診察のページへの入口として置いた見本の
  行は、診察の一覧の行に置き換わった（裁定記録「診察のページへの入口」）

### 色と大きさ

- ナビゲーションの面は見出しの帯と同じ V78 で塗り、カードの V77 と分ける。
  開いている行き先の塗りは V26、そのアイコンは V27、名前とほかのアイコンは V4 で描く
  （見え方記述 V91〜V94。裁定記録「ナビゲーションの面の色」）
    - TASK0029 で色の当て方を Material の既定へ寄せた。面と、名前とほかのアイコンは
      既定に任せ（V91・V94 は欠番）、塗りとそのアイコン（V92・V93）だけを残した。面は
      既定の `surfaceContainer`（V77）で、見出しの帯もそれにそろえた。カードは地と帯の
      中間（V100）にして、ナビゲーションと分けたままにした
- アイコンは 32 dp にする（Material の既定は 24 dp。見え方記述 V98。裁定記録
  「ナビゲーションのアイコンの大きさ」）
- ナビゲーションの高さは 68 dp である（Material の既定は 80 dp。見え方記述 V95。裁定
  記録「ナビゲーションの高さ」）

| 入力 | 出力 |

| 送った後、指で 24 dp 以上戻す（払って慣性で戻すのも同じ） | 先頭へ戻る前にナビゲーションが出る |
| 送った後、アプリが先頭の方へ送る | 畳んだまま |

## 実装計画

1. 下端の高さの基準を測る: 最大の文字で、今日のページの記録の欄の縦を起動直後と送った後で
   測り、テストに固定する（ナビゲーションを足す前の値）。あわせて、80 dp を足したときに
   起動直後の本体がはみ出すかを、試しの枝で測る。はみ出すなら、ステップ 2 へ進まず、
   測った値を添えて遷移の形の裁定を仰ぎ直す
2. ルーティング: `StatefulShellRoute` へ移し、経過・診察と診察の下の画面を中身の無い
   画面で足す。戻る操作と、行き先の再押下。ルーティングのテスト
3. 下端のナビゲーション: 外枠に足し、注意書きと一緒に畳む。キーボード・読み上げ・動きを
   減らす設定。外枠のテスト
4. 中身の無い画面: ARB・題名・1 文・見本の入口。ウィジェットのテスト（最大の文字・押せる
   大きさを含む）
5. 見え方記述: ナビゲーションの色と大きさの値・R3 の例外（裁定による）・
   appearance-derive・色の自動テスト
6. 実機の検証: 見え方・TalkBack・最大の文字サイズ・戻る操作
7. ドキュメント: 機能への反映
8. 自己コードレビュー（CP5）と第三者視点レビュー（CP6）

各ステップの末でコミットし、`scan_diff.py` で規模を測って自己コードレビューを回す。

#### 実機

[実機・エミュレータで確かめる](../references/device-check.md) の手順で release ビルドを
入れ、読み取りで画面の文言を確かめながら押す。結果は検証項目のチェックリストに同じ名前で
置く。

**adb での確かめ方**: 本作業でエージェントが回した形である。コマンドの意味と守ることは
device-check.md にある。`<id>` は `adb devices -l` の 1 列目で、Git Bash では端末側の
パスを渡す行に `MSYS_NO_PATHCONV=1` を前に付ける。

1. 端末の設定を読む。文字の倍率と、px から dp へ直す密度を控える（dp = px × 160 ÷ 密度）

   ```sh
   adb -s <id> shell settings get system font_scale
   adb -s <id> shell wm density
   adb -s <id> shell wm size
   ```

2. 作業ツリーの今の版を入れて開き直す。`force-stop` で、前の状態（畳んだままなど）を
   持ち越さない

   ```sh
   flutter build apk --release
   adb -s <id> install -r build/app/outputs/flutter-apk/app-release.apk
   adb -s <id> shell am force-stop cc.updater.condition_log
   adb -s <id> shell am start -n cc.updater.condition_log/.MainActivity
   ```

3. 撮影と読み取りを対で取る（device-check.md の 3 と 4）。下端の部品の範囲は、読み取りの
   `content-desc` が「記録 タブ: 1/3」の要素（ナビゲーション）と、注意書きの文の要素の
   `bounds` で見る。画像だけでは、余白がどの部品のものかを見分けられない
4. 送る。指を `y1` から `y2` へ 400 ms で動かす。y1 > y2 で画面の下の方へ送り、
   y1 < y2 で先頭の方へ戻す。各操作の後に 3 を取り直す

   ```sh
   adb -s <id> shell input swipe 360 1100 360 500 400
   adb -s <id> shell input swipe 360 600 360 700 400
   ```

5. 押す。境目を見るときは、境目の数 px 上を押す（device-check.md の 5）。押した後に 3 で
   選択中の行き先（`selected="true"`）と、ダイアログ（「閉じる」）の有無を見る
6. 取ったファイル（`build/*.png`・`build/*.xml`）は確かめ終えたら消す

### FEAT0002

外部仕様(what):
- 今日・経過・診察の画面の下端にナビゲーションがあり、押すとその行き先が開く。
  並びは診察・今日・経過で、起動すると今日の記録が開く
- ナビゲーションの名前の文字は、OS の文字の大きさによらず同じ大きさである。長押しで
  出るツールチップは、OS の文字の大きさのまま名前を示す
- 経過と診察は中身の無い画面で、題名と、何の画面かと準備中であることを示す 1 文を
  示す。診察の画面の見本の行から、見本の診察のページと、その下の 2 つの画面へ移れる

  先頭へ戻すと出る。スクリーンリーダーを使っている間は畳まない。キーボードが出ている間
  は出さない
- 経過・診察の先頭の画面で戻る操作をすると、今日の記録へ戻る

内部設計(how):
- ルーティングは行き先ごとに画面の積み重ねを持ち、外枠がすべての画面を包む
- ルーティングが位置から、下端のナビゲーションを出す画面かを決めて外枠へ渡す
- 行き先は 1 つの列挙に持ち、ルーティングとナビゲーションはそこから作る
