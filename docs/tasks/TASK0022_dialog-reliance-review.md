# ダイアログに頼る画面を見直す

## 目的

読み上げを使う人も使わない人も、選ぶ・書く・確かめる操作を、迷わずに始めて終えられる
ようにする。ダイアログで行っている操作のうち、ページや画面の中の部品の方が合うものを
移す。

## 目標

- アプリのダイアログを種類で分け、ダイアログのまま残すものと、ページや画面の中の部品へ
  移すものを決める
- 移すと決めたものを移す。残すものは、閉じるボタンを中に持つ形を保つ

## 非目標

- 確かめ・判断のダイアログ（診察を消す・今日の診察を足す・同じ日の診察）を、理由なく
  ページへ移さない。操作を止めて決めてもらう用途は、Material のダイアログの使いどころで
  ある
- TalkBack が前に読んだ項目へ戻る振る舞いを、アプリの側で打ち消さない（TASK0015 の
  裁定記録「ダイアログの背景の読み上げ」）

## 問題

- アプリはダイアログを 9 つ持つ（TASK0015 の時点）。種類で分けると次のとおりである

| 種類 | 該当 | 見立て |
|---|---|---|
| 確かめ・判断 | 診察を消す・今日の診察を足す・同じ日の診察 | ダイアログが合う |
| 選ぶ | 設定の時刻（24 件）・受診先を選ぶ | 件数が多いと、ページか画面の中の選択肢の方が見通しやすい |
| 書く | 受診先の名前（3 つの欄）・気を付けることの名前 | 欄が複数あるなら、ページの方が広く使え、キーボードと競合しない |
| 知らせ | 「このアプリについて」 | 本文が長く、ページでもよい |
| 日付 | 日付を選ぶ（Flutter が作る） | Material の標準の部品で、作り替える理由は弱い |

- TASK0015 の TalkBack の確かめで、ダイアログを開き直すと、閉じる前に最後にフォーカス
  していた項目から読まれた（背景の「閉じる」・「キャンセル」）。ページでも同じことが
  起きるかは確かめていない
- 行の ⋮ のメニュー（受診先・気を付けること）も背景を持ち、TalkBack は背景を「閉じる」と
  読む。開き直したときの読まれ方もダイアログと同じだった（TASK0015 の TalkBack の
  確かめ。ユーザーが耳で確かめた）。メニューは Flutter の `PopupMenuButton` が開き、
  ダイアログと同じ開き方の差し替えでは背景を外せない
- 気を付けることの名前のダイアログは、TASK0026 が名前の変更を直し、TASK0018 が編集の
  画面の形を問う。重なる
- 見直しは TalkBack だけでなく、iOS の VoiceOver の閉じ方（二本指で Z を描く操作）と
  読まれ方でも比べる。ダイアログは背景を読み上げから外しており、Z はエンジンの画面の
  側が `popRoute` で受ける見込みである（TASK0015 の第三者視点レビュー。Mac で確かめる）
