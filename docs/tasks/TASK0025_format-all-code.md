# コード全体を dart format で整える

## 目的

コードを書き換えるたびに書式の割れで手間を払わないようにする。整形器を回しても、
変更した箇所だけが差分に出るようにする。

## 目標

- `lib/` と `test/` の手で書いたコードを、`dart format` の既定の設定で整える
- 整える変更を、振る舞いを変えるコミットと分ける
- 整えた状態を保てるように、整える・確かめるコマンドを CONTRIBUTING「開発のコマンド」へ
  書く

## 非目標

- 整形器の設定を変えること（既定のまま。TASK0002 の裁定「dart format」）
- 生成したコード（`*.g.dart`・`lib/l10n/app_localizations*.dart`・`test/drift/`）を
  手で整えること
- 整えていないコードを機械で拒むこと（コミットの hook・テスト）。CI が無く、拒む場所を
  決める設計が要る

## 問題

- リポジトリには 2 つの書式が並ぶ。旧来の書式（引数を抱き込み、末尾のカンマを付けない）
  と、今の既定の書式（1 引数ずつ並べ、末尾にカンマを付ける）である。言語の版が 3.7 以上
  なので、`dart format` は旧来の書式のファイルを書き直す
- TASK0002 の裁定「dart format」は、全体の整形を別のブランチで行うと決めた。それを行う
  作業が無かった
- TASK0015 は、既存のファイルを整えず、新しいファイルだけを整えると決めた。TASK0024 では
  整形器が既存の 4 ファイルを書き直し、戻して手で当て直した
- 整えると、`git blame` が整形のコミットを指す。`.git-blame-ignore-revs` で外せる
- 整形器を回す手順は、どのドキュメントにも書いていない（CONTRIBUTING・README・
  `docs/references/` を `dart format` と「整形器」で引いて 0 件）
- 測った規模（2026-10-08・Dart 3.13.4。TASK0026 の起票を入れた main から切った
  worktree で、いったん整えて測り、戻した）: 手で書いたファイル 120 のうち 64 が変わる
  （`lib/` 32・`test/` 32）。差分は +2153 −1682 行。生成したファイルは 1 つも変わらない。
  64 ファイルとも、空白とカンマを除くと HEAD と一致した（検査は、書き足した 1 行を拾う
  ことで較正した）

## 概要設計

- **整える範囲**: `dart format lib test` を回す。生成したファイルも範囲に入るが、既定の
  設定では変わらない（測った規模）。生成し直すと書式が変わる生成器が出たら、そのときに
  範囲を分ける
- **コミット**: 整形だけのコミット `style(TASK0025): format all code` を 1 つ作り、
  ドキュメントのコミットと分ける。main へは squash で 1 つのコミットになるが、ブランチに
  振る舞いを変える変更が無いので、整形と振る舞いは分かれたままである
- **CONTRIBUTING**: 「開発のコマンド」の最初のコマンドのブロックの後に、コミットの前に
  整えることと、2 つのコマンドのブロックを足す。整えるコマンドは `dart format lib test`、
  確かめるコマンドは `dart format --output=none --set-exit-if-changed lib test` で、
  0 以外で終われば整えていないファイルがある
- **等しさの検査**: 変わったファイルごとに、HEAD の内容と今の内容から空白とカンマを除いて
  比べる。整形器が字句を足し引きしていないことを、テストと別の経路で確かめる。文字列の
  リテラルの中の空白の変化は見ない（整形器はリテラルの中身を書き換えない）

`flutter test` の 2 つの経路で確かめる。実機の検証はしない。

  検査は、1 行書き足したファイルを 1 件として拾うことで較正した
- [x] **生成したファイル**が `git diff --name-only` に出ない（`*.g.dart`・
  `app_localizations`・`test/drift/` の 0 件）
- [x] **静的解析とテスト**: `flutter analyze` 0 件、`flutter test` 563 件が通過（失敗 0・
  スキップ 0）

### CP6 の提案の根拠

差分は 64 ファイル・約 3800 行で、走査すれば full になる見込みである。ただし変更は
整形器が機械で作るもので、判断を含む変更は CONTRIBUTING の数行だけである。振る舞いを
変えないことは、字句の等しさの検査（較正済み）とテストの全件の 2 つの経路で確かめる。
観点ごとのレビューが新しく見つけられるものは少ないと見て、不要を提案する。
