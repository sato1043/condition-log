# 記録を書き出し、別の端末へ戻せるようにする

## 目的

機種変更や端末の紛失で記録を失わないように、本人の操作で記録を書き出し、別の端末へ
戻せるようにする。

## 目標

- 記録（体調・気を付けること）を、本人の操作で書き出せる（SREQ0012）
- 書き出したものを別の端末で読み込み、記録を戻せる（SREQ0012）

## 非目標

- アプリから外部へ送信しない。書き出したものを置く先は、本人が OS の共有・ファイルの
  保存で選ぶ

## 問題

- 書き出したものは端末の外に出る。置き場所によってはクラウドへ渡る。
  `requirements.md`「プロジェクト憲章」の問題が挙げる、本人の操作で記録を端末の外へ
  出す経路にあたる
- 書き出す形式は、[DB の表と関係（ER 図）](../references/database-schema.md) が並べる表の
  すべてを含む
- 使っていない受診先も書き出す。それを選んだ診察が名前を出すためである（TASK0015）
- app_settings の `usual_care_provider` は、受診先の id を値に持つ論理参照で、外部キーが
  守らない。読み込みで受診先の id を付け替えるなら、診察の `care_provider_id` と同じ対応で
  この値も付け替える（TASK0015）
- app_settings の `about_app_shown`（初めて起動したときに「このアプリについて」を示した
  印）は移さない（TASK0024）。読み込む先の端末のこの行の扱いは残課題にある
- 診察の一覧で選んだ絞り込みは、受診先の id をアプリが動いている間メモリに持つ。読み込みで
  id を付け替えると、動いているアプリの絞り込みは古い id を指したまま残る（TASK0015）
- DB を開くと `PRAGMA foreign_keys = ON` が立つので、読み込みは受診先を診察より先に
  入れる。気を付けることをその印より先に入れるのと同じ型である（TASK0015）
- 読み込む受診先の名前は、名前の規則（`lib/domain/name.dart` の `nameOf`。いまは前後の
  空白を除いて空を拒むだけ）で検証する。長さ・制御文字・幅の無い文字の扱いは、読み込みを
  作るときに決める。全角の空白だけの名前は DB の CHECK を通るが、読み出しは名前の無い
  受診先として扱う（TASK0015）
- 気を付けることの項目は、名前と気を付け方の組で見分ける。気を付け方は `refrain`・
  `keepUp` の文字列で、表の CHECK がそれ以外を拒む。書き出しがこの値をそのまま持つと、
  値の名前が端末の外との約束になり、後で列挙の名前を変えると、DB の移行だけでは古い
  書き出しを読めなくなる（TASK0026）
- 項目の表は、名前と気を付け方の組を一意に保つ。既存の記録へ結合する読み込みは、同じ
  組の項目を足すと制約で失敗するので、既存の項目の id へ印を付け替える対応が要る
  （TASK0026）
- 版 3 以下の形の DB は、版 4 以上のビルドが開くと、移行の段がすべての表を消す。
  書き出しの形式を DB のファイルそのものにすると、古い書き出しの読み込みは失敗せず、
  空の記録で終わる。残課題「スキーマの版が違う書き出しを読み込むときの扱い」の前提に
  なる（TASK0026）
- 版 3 までの記録は気を付け方を持たず、印の向きも逆である（その行動をした日に付けて
  いた）。値を補って読み込む道は無い（TASK0026）
- 気を付けることの名前は、項目を見分ける鍵と、足す欄の候補を探す鍵である。比べ方は
  文字列の完全一致で、名前の規則は前後の空白を除くだけである。全角と半角・途中の空白の
  幅・合成の形（NFC と NFD）・幅の無い文字が違う名前は、見た目が同じでも別の項目に
  なる。使っていない項目は戻らずに新しい項目ができ、同じ行動の印が 2 つの項目に
  割れる。項目は消せないので、割れた印は寄せられない。読み込みができると、外から来た
  名前もこの比べ方に乗る（TASK0026 の CP6 から）
    - 足す欄の断りの知らせは、打った名前と気を付け方が一覧の項目と等しいかで出す
      （`lib/features/daily_log/ui/add_precaution.dart`）。比べる形を広げるときは、
      リポジトリの断りと知らせが食い違わない形にする
    - 配った後で同じとみなす範囲を広げると、既にある項目どうしが同じ組になり、印を
      寄せる移行が要る
- 端末の紛失に備えるには、紛失より前に書き出してある必要がある

## stakeholder 未裁定の残課題

- 書き出す形式と、書き出したものにパスワードを付けるか
- 読み込むとき、既存の記録へ上書きするか、結合するか
- 上書きで app_settings を置き換えるとき、読み込む先の端末の `about_app_shown` を残すか。
  消すと、その端末で既に閉じていても次の起動でもう一度示す（TASK0024 の CP6 から）
- スキーマの版が違う書き出しを読み込むときの扱い
- 読み込む記録の日付を検証すること。表の制約は日付の形（`YYYY-MM-DD`）だけを縛るので、
  暦に無い日（`2026-02-30`）も入る。入ると、その 1 行で診察の一覧と推移の読み出しが
  丸ごと失敗する。アプリだけが書く今は入らない（TASK0014 の CP6 から）
- 書き出しを本人へ促すか。促すなら時機と頻度
- 気を付けることと受診先の名前を、同じとみなす範囲（全角と半角・空白の幅・合成の形・
  幅の無い文字）と、長さ・制御文字の扱い。受診先の名前だけでなく、項目を見分ける鍵で
  ある気を付けることの名前にも効く。読み込みを待たずに決めるかも含む（TASK0026 の
  CP6 から。推奨を示していない）
