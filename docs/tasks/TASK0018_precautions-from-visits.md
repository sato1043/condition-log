# 診察で言われた気を付けることを、その日からの体調記録で付ける

## 目的

医師に言われた気を付けることを診察で書き留め、その日からの体調記録で、できた日を
付けられるようにする。

## 目標

- 診察のページから、気を付けることの一覧を編集できる
- 編集した気を付けることを、その診察に結びつけて記録する。どの診察で言われたかを後で
  見返せる
- 診察で決めた気を付けることの一覧が、その診察の日からの体調記録で、できた日を付ける
  一覧になる

## 非目標

- 診察で聞いたこと（欄の文）から、気を付けることを自動で取り込まない（TASK0014 の
  非目標を引き継ぐ）
- 気を付けることができたかを評価しない。体調との関係を判定しない（憲章の非目標）
- 既存のデータ（今の気を付けることの一覧と印）を、新しい持ち方へ移さない

## 問題

- 今の一覧は、全体で 1 つ（表 `precautions`）である。使うかどうか（`in_use`）
  だけを持ち、いつから効くかを持たない。日ごとに一覧が変わるには、診察の日を起点にした
  持ち方が要り、表を変えてスキーマの版を上げる。TASK0017 も版を上げるので、順に積む
- 今は、使わなくした項目も、印を付けた過去の日のページには残る（FEAT0001）。日ごとに
  一覧が変わると、過去の日にどの一覧を見せるかの規則がこれに替わる
- 診察は日付を変えられ、消せる（FEAT0003）。どちらも、その後の日の一覧を変えうる
- 今日以後の日付の診察（予定）も、同じページで書ける
- 受診先が複数あると、診察ごとに言われた気を付けることが重なりうる
- 一覧の編集は、今日のページの「編集」から開く画面にもある。TASK0026 がその画面の名前の
  変更を直す
- TASK0014 は、医師の言葉は一覧の項目の出どころになるが、アプリは両者をつないでいないと
  書いた（裁定記録「要求の採番」）。この作業がつなぐ

## 裁定記録

- **起票**（2026-10-07・ユーザー）: 診察のページで気を付けることを編集できるようにする。
  TASK0015 のブランチで起票し、そのコミットに混ぜてよい
    - 「編集」は 3 つを合わせて指す。一覧そのものを編集する。診察に結びつけて記録する。
      その診察で言われた一覧が、その日以降の体調記録でできた日を付ける一覧になる
- **既存のデータの移行**（2026-10-07・ユーザー）: 既存のデータを新しい持ち方へ移すことを
  非目標に置く。スキーマの版を上げる移行の段は持つ（CONTRIBUTING「開発のコマンド」）
- **既存のデータを消す**（2026-10-07・ユーザー）: 版を上げるとき、DB 全体（体調の記録・
  気を付けることと印・診察・受診先・設定）を消し、空の DB から始めてよい。TASK0017 と
  同じ裁定である
    - 代償: 本人の端末の記録も消える

## stakeholder 未裁定の残課題

- 優先度の 4 軸と `hazard` が未記入である
- 移さない既存のデータを、残して見せるか（読むだけにするか）、消すか
    - 解消: 裁定記録「既存のデータを消す」で、DB 全体を消してよいとした（解消 2026-10-07）
- 一覧が変わらない診察（気を付けることに触れなかった診察）は、前の一覧をそのまま引き継ぐか
- 最初に一覧を決めた診察より前の日と、診察を書かない人の体調記録に、どの一覧を出すか
  （今の全体の一覧を残すか）
- 今日のページの「編集」を残すか。残すなら、そこでの編集はどの日から効くか
- 今日以後の日付の診察で一覧を変えたとき、その日から効くか
- 診察の日付を変えた・診察を消したときに、付けた印をどう扱うか
- 受診先ごとに言われた気を付けることを、1 つの一覧へ合わせるか、受診先ごとに分けるか
- 気を付けることの編集で、使う項目と使わない項目を 2 つの一覧に分けるか、1 つにまとめるか
  （2026-10-07・ユーザーの問い）。まとめる形は、使わない項目を控えめの色にし、読み
  上げで「名前（使わない）」と添える
    - 分ける利点: 毎日使う項目だけが一続きに並ぶ。使わない項目は時間とともに溜まる。
      並べ替えの対象が使う項目に限られる
    - まとめる利点: 使う・使わないを切り替えても項目が動かず、読み上げのフォーカスも
      動かない。切り替えをスイッチにすれば、状態の変化は標準の仕組みで読まれ、移した
      ことを告げる読み上げの欄（TASK0015）が要らなくなる
    - まとめるときの制約: 使わない項目も名前を直す・使うに戻すを持つので、文字の
      コントラストは 4.5:1 を保つ。色だけで区別しない（見え方記述・WCAG 1.4.1）ので、
      見える文字でも「使わない」を添える
    - TASK0015 は分けたままにし、使うで戻した項目をなるべく元の位置へ置き、移したことを
      読み上げで告げた（TASK0015 の裁定「使わないの知らせ」「移したことの読み上げ」）
    - 受診先の画面も同じ形である。件数が少ない見込みで、まとめても困りにくい
- 気を付けることの項目を消せるようにするか（2026-10-07・ユーザーの指摘）。今は消さずに
  使わないにする作り（TASK0002）で、打ち間違えた・試しに足した項目が「使っていない
  項目」に残り続ける。名前は直せる
    - 案 A: 印の無い項目だけ消せる。記録を失わない。消せない理由を画面で伝える
    - 案 B: 確かめのダイアログを経て、印ごと消す。過去の日の記録と、体調と重ねて
      見る材料（SREQ0008）が減る
    - 案 C: 今のまま、使わないにするだけにする
    - 過去の日にどの一覧を見せるかの規則（この作業で作り直す）と切り離せないので、
      ここで決める。エージェントの推奨は A（記録を失わず、間違えて足した項目は消せる）。
      確かめを先に置く形は、診察の削除（TASK0014）と揃う
    - 受診先も消せない（TASK0015 の裁定「受診先の消し方」が代償として受け入れた）。
      揃えるかを同時に決める
- 推移の画面（TASK0006・SREQ0008）・書き出し（TASK0010）での見せ方
- 実現する提供要求を、SREQ0002 を改めて覆うか、新しく採番するか（spec-derive で判断する）
