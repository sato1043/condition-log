# 診察の会話を録音し、聞き返しながら記録する

## 目的

診察で医師と話したことを録音しておき、後で聞き返しながら診察の記録を書けるようにする。

## 目標

- 診察のページから、その診察の会話を録音できる
- 録音をその診察に結びつけて残し、診察のページで聞き返せる
- 聞き返しながら、同じページの欄（診察で聞いたこと等）を書ける
- 音声は、内容が聞き取れる程度の音質に抑え、記録の大きさを小さく保つ

## 非目標

- 文字起こし（TASK0020 が扱う）
- 録音した音声から情報を読み取り、アプリの入力へ反映すること
- 録音を端末の外へ送ること（憲章の非目標）
- 既存のデータを新しい持ち方へ移すこと

## 問題

- アプリは今、OS の権限を 1 つも求めていない（Android のマニフェストに
  `uses-permission` が無い）。録音はマイクの権限を初めて求める。憲章の目標「OS へ
  求める権限を必要最小限にする」と照らし、求める時機（初めて録音するとき）と、断られた
  ときの案内を決める必要がある
- 診察は数十分続くことがあり、その間に画面が消えたり、アプリが背景へ移ったりする。
  Android ではマイクを使うフォアグラウンドサービスと、その種類の宣言が要りうる。iOS では
  背景での音声の扱いを Info.plist に宣言する（Mac で作業するとき）。マイクの用途の説明
  （`NSMicrophoneUsageDescription`）も同じく要る（Mac で作業するとき）
- 録音と再生のパッケージを足す。足す前に、pub.dev で Android と iOS の両方に対応する
  ことを確かめる（CONTRIBUTING）。外部へ送信しない制約（憲章）のために、マニフェストの
  合成で持ち込まれる権限（`INTERNET` 等）と、利用状況を送るかも確かめる。足した後の
  release のマージ済みのマニフェストの権限を、足す前のものと比べる（TASK0015 の第三者
  視点レビューで挙がった）
- 音声は DB の外のファイルに置き、DB の行から指す形になりうる。診察を消したとき・
  DB を消したときにファイルが残らないようにする必要がある
- 音声は医師の声を含む。記録は端末の中にだけ置くが、書き出し（TASK0010）で端末の外へ
  出る経路があり、大きさも記録の形も増える
- 医療機関によっては院内の録音を断っていることがある（一般的な事情からの推論で、
  確かめていない）

## 裁定記録

- **起票**（2026-10-07・ユーザー）: 診察のページで医師との会話を録音し、後で振り返り
  ながら記録できるようにする。TASK0015 のブランチで起票し、そのコミットに混ぜてよい
    - 音質は、記録が大きくならないよう、内容が聞き取れる程度のやや悪い音質を想定して
      よい
    - 文字起こしは別の作業書にしてよい（TASK0020 として起票した）
    - 文字起こしのテキストから情報を読み取って入力へ反映することは検討しない
- **既存のデータの移行**（2026-10-07・ユーザー）: 既存のデータを新しい持ち方へ移すことを
  非目標に置く。スキーマの版を上げる移行の段は持つ（CONTRIBUTING「開発のコマンド」）
- **既存のデータを消す**（2026-10-07・ユーザー）: 版を上げるとき、DB 全体を消し、空の DB
  から始めてよい。TASK0017・TASK0018 と同じ裁定である
    - 代償: 本人の端末の記録も消える

## stakeholder 未裁定の残課題

- 優先度の 4 軸と `hazard` が未記入である
- 1 件の診察に録音を何本持てるか（1 本か、途中で止めて足せるか）
- 音声の形式とビットレート（例: AAC か Opus、モノラル、16 kHz 前後）。1 時間あたりの
  大きさの目安
- 録音の前に、医師の了解を得るよう本人へ促すか
- 録音を消せるか。診察を消したときに録音も消すか
- 画面が消えている間・アプリが背景にある間も録音を続けるか
- 聞き返す部品の操作（再生・一時停止・送り・戻し・速さ）と、欄を書く間の置き場所
- 書き出し（TASK0010）に録音を含めるか
- 実現する提供要求を、SREQ0013 を改めて覆うか、新しく採番するか（spec-derive で判断する）
