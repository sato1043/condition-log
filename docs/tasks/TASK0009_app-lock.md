# アプリにロックをかけられるようにする

## 目的

端末を家族と共用していても、記録を本人だけが見られるようにする。

## 目標

- 生体認証または PIN コードで本人を確かめてからアプリを開く、ロックのオプションを
  設ける（SREQ0011）
- オプションの既定は無効（認証なし）とする（SREQ0011）
- オプションを有効にしたとき、タスク切り替え画面に記録の内容を出さない（SREQ0011）

## 非目標

- ロックを既定で有効にしない。体調が悪い日の操作量を増やさない
- DB を暗号化しない（TASK0002 の裁定）

## 問題

- PIN を忘れると記録へ入れなくなる。記録は端末内にしか無いので、解除の経路を誤ると
  記録をすべて失う
- 生体認証は OS へ求める権限を増やす。`requirements.md`「プロジェクト憲章」の目標
  「OS へ求める権限を必要最小限にする」と照らす
- iOS では `Info.plist` に生体認証の利用の理由の文言が要る（Mac で作業するとき）
- 守る中身に、診察の記録（薬や指示の変更を含む「診察で聞いたこと」）が加わった
  （TASK0014 の CP6 から）。オプションを決めるときの材料:
    - 診察のページを開いたまま切り替えると、2 つの欄の本文がタスク切り替え画面に映る
    - 診察の一覧の行は、欄の 1 行目を読み上げが声に出す（TalkBack で確かめた。VoiceOver は
      未確認）
- 守る中身に、受診先の名前（病院・診療科・医師）が加わった。どこへ通っているかは病気を
  推し量らせる（TASK0015）。オプションを決めるときの材料:
    - いつもの受診先を決めると、診察の一覧を開くたびに絞り込みの部品がその名前を出し、
      読み上げも声に出す
    - 使わないにした受診先も、名前は端末に残る
    - 診察のページは、見出しの帯の直下に受診先の名前を出す。タスク切り替え画面に最も
      映りやすい位置である
    - 名前を出す部品の一部は、シェルの外に出る。名前・選ぶ・絞り込みのダイアログは
      ルートのナビゲーターに、受診先の行のメニューも同じくルートのナビゲーターに出る。
      ロックの覆いは、これらより上（`MaterialApp.builder` 等）に置く
    - 受診先と気を付けることを使わない・使うで移すと、読み上げだけの欄が名前を声に出す
      （「〜を使っていない受診先へ移しました」）。欄はアプリの根の
      `MaterialApp.builder` で全ページを包む `SpokenStatus` にある。画面には何も描かない
      が、文言は告げてから 5 秒の間、読み上げの木に残り、他のユーザー補助のアプリからも
      読める。覆いは `SpokenStatus` の外側に置くか、ロックの間は欄を空にする。
      「使わない」の後の SnackBar は TASK0015 で外した
- TASK0002 の裁定「DB を暗号化しない」の根拠の 1 つ「暗号化は後から `rekey` で足せる」は、
  SQLite の版の選び方で成り立たないことがある（TASK0002 の CP6 から）。暗号化を
  見直すときの材料:
    - sqlite3 3.x では、暗号化の版を build hook の `source`（`sqlite3mc`・`sqlcipher`）で
      選ぶ（sqlite3 の `doc/hook.md`）
    - SQLCipher の `PRAGMA rekey` は平文の DB を暗号化できず、`sqlcipher_export()` で
      移す。Android では OpenSSL をリンクする
    - SQLite3MultipleCiphers の `PRAGMA rekey` は平文の DB を暗号化できる。ただし
      ジャーナルモードが WAL 以外のときに限る

## 裁定記録

- **ロックの形**（2026-10-01）: 生体認証または PIN コードによるロックを、既定で無効の
  オプションとして設ける。同じオプションでタスク切り替え画面の見え方も変える
    - 根拠: 端末を共用する家族の閲覧は、DB の暗号化では防げない。PIN なら体調が悪い日
      でも入力できる。既定を無効にすれば、ロックを要しない利用者の操作量は増えない
    - 経緯: TASK0002 の分析で、DB の暗号化が守る相手を整理したときに切り出した。
      最初から実装する機能ではないと判断し、後日の作業とした
- **要求の採番**（2026-10-03・ユーザー）: 新しい BREQ0006 を由来に SREQ0011 を採番した
    - 根拠: 既存の BREQ はどれも閲覧の制限を扱わない
- **空の「実現機能」の食い違い**（2026-10-03・ユーザー）: 受容する。SREQ0011 の
  「実現機能: （未採番）」は、機能を生む作業まで照合の食い違いとして鳴ったままにする
  （TASK0002 の同じ裁定に揃える）
    - 経緯: 空の記法を規範と走査器へ足すことは、~/.claude の作業として起票した

## stakeholder 未裁定の残課題

- PIN を忘れたときの解除の経路（OS の端末認証で代える等）
- PIN の桁数と入力 UI（体調が悪い日でも入力できる形）
- PIN の保存の方式
- アプリがバックグラウンドへ移ってから再びロックするまでの時間
- 生体認証を使えない端末での扱い
- 使うパッケージと、その Android・iOS の両対応
- 消した記録が DB ファイルの空き領域に残りうる。`PRAGMA secure_delete` を有効にするか
  （DB 全体の設定で、毎日の記録の削除にも及ぶ。端末を人に渡す場面の守りとして決める。
  TASK0014 の CP6 から）
