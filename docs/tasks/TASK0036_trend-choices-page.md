# 経過の選択を、要約の行と下のページへ移す

## 目的

経過の一覧の上に並ぶ選択の欄を 1 行にまとめ、一覧に並ぶ日を増やす。期間・項目・気を
付けることの選択は、経過の下のページで行う。欄が一覧の場所を奪うこと、欄が切れて続きが
見えないことを、形から無くす。

## 目標

- 経過の上の 3 つの選択の欄を、今の選択を示す 1 行（要約の行）へ替える。行を押すと、
  選択のページを開く（SREQ0007）
- 選択のページで、期間・項目・気を付けることを、その場に並ぶ選択肢から選べる。選んだ
  時点で、経過の一覧へ効く（SREQ0007・SREQ0008）
- 選択のページから、戻る操作で経過へ帰る。選んだ内容は、帰っても保つ（SREQ0007）
- 要約の行は、期間と項目をいつも示し、気を付けることは、1 つを選んでいるときだけ示す
  （SREQ0008）

## 非目標

- 選択の種類・選択肢に出す範囲・既定・選択を保つ間（アプリを動かしている間）を
  変えない。TASK0006 と TASK0035 が決めた規則のままにする
- 選択のページに、確定のボタンと取り消しを置かない。選ぶと自動で経過へ戻る動きも
  入れない（裁定記録）
- ページの移り方を独自に決めない。ほかの下のページと同じく、OS ごとの Material の既定に
  任せる
- 一覧の行の形・行の印・月と診察日の区切り・日のページを変えない
- 設定と診察の選択の欄（`ChoiceField`）と、選択のダイアログを変えない
- DB の表を変えない

## 問題

- 今の経過のページ（`lib/features/trend_review/ui/trend_review_page.dart`）は、上に選択の
  欄（`ChoiceField`）を 3 つ縦に並べ、欄を押すとダイアログで選ぶ。選んだ値は、欄ごとの
  provider がアプリの動いている間持つ（`lib/features/trend_review/ui/providers.dart`）
- 欄が一覧の場所を残さない大きさ（iOS の最大の文字・横向きの画面）では、欄が自分の
  場所の中で送れる。欄と一覧の高さの分け方は、自前の配置（`CustomMultiChildLayout`）が
  持つ。TASK0035 が、3 つ目の欄を足したときに入れた形である
- この形へ、TASK0035 の第三者視点レビューが 8 件（中 5・低 3）を挙げた。レビューの
  ときに、使い捨てのテスト（テストのフォント）と実機で確かめた点は次のとおりである
    - 横向きの画面と iOS の最大の文字（AX5）では、欄の場所が 0 dp になり、欄に届かない。
      33 px のはみ出しの例外も出た。Android の文字の倍率 2.0 の横向きでは、欄の場所は
      67 dp だった
    - 横向きの画面（640 x 360 dp・既定の文字）で一覧を送ると、下端のナビゲーションが
      畳みと復帰を繰り返した（約 70 フレームで 24 回）
    - 縦向き（360 x 640 dp）の Android の文字の倍率 2.0 でも、13 字の名前の項目を選ぶと、
      欄が 69 dp ぶん切れた。今日の行は全体が見えた
    - 欄が切れているとき、続きが在ることを示すものが無い。実機の横向き（既定の文字）で、
      欄は 2 つ目の下の空きでちょうど切れ、3 つ目が在ることが送るまで分からなかった
    - 気を付けることを 1 つ選んだまま欄が切れていると、印が減っている理由が画面に出ない
- 要約の行へ替えると、上の点の元になる形（3 つの欄の高さを一覧と分け合う）が無くなる
  見込みである（コードからの推論。測っていない）。自前の配置と、欄の送りは、要らなく
  なる。ナビゲーションの畳みと復帰は、欄の送りが元かを確かめていない。替えた後に、
  同じ条件で測り直す
- 要約の行も、大きい文字では折り返す。折り返した行が一覧の場所をどれだけ取るかは、
  測っていない。最大の文字と横向きの画面で、今日の行の全体が見えることを確かめる
- 選択を 1 つ替える操作は、今の 2 回（欄・選択肢）から 3 回（要約の行・選択肢・戻る）へ
  増える。この代償は受け入れた（裁定記録）
- 経過の下のページは、今は日のページ（`/review/day/:day`）だけである。下のページは
  下端のナビゲーションを出さない（`lib/app/router.dart` の `_showsDestinations`）。選択の
  ページの場所を足す。場所は、アプリが作る固定の語だけを持つ
- ページの移り方の既定は、Android が `PredictiveBackPageTransitionsBuilder`（戻る動作の
  外では、新しいページが右から入りながら現れる `FadeForwardsPageTransitionsBuilder` の
  描き方）、iOS が `CupertinoPageTransitionsBuilder`（横からのスライド）である
  （`material_ui` 1.5.0 の `page_transitions_theme.dart` で読んだ）。アプリは移り方を
  指定していない。iOS での見え方は実機で確かめる（Mac で作業するとき）
- 選択肢は、読み出しに依る。期間の「前回の診察から」は、今日より前の診察が在るとき
  だけ出る。気を付けることは、期間の記録が読めるまで「すべて」だけである。選択の
  ページは、読み出しの待ちと失敗を、自分で扱うことになる
- 選んだ気を付けることが選択肢に無いときは「すべて」として扱う規則が在る（TASK0035）。
  選択のページと要約の行の両方が、同じ読み方をする必要が在る
- 経過のページのテスト（`test/features/trend_review/ui/trend_review_page_test.dart`）は
  65 本で、欄を押してダイアログから選ぶ補助（`choose`・`choosePrecaution`）を使う。
  `choose` の呼び出しは 23 か所在る（2026-10-12）。補助を選択のページを通る形へ替える
- 読み上げ（意味の木）の形を決める。要約の行は押せる 1 つの節で、名前に今の選択を
  持つ。選択のページは、3 つの見出しと、選んだ状態を持つ選択肢である。声では確かめて
  いない（TalkBack は Android の実機で、VoiceOver は Mac で作業するとき）

## 裁定記録

- **起票**（2026-10-12・ユーザー）: TASK0035 の第三者視点レビューの指摘（選択の欄が場所に
  収まらないときの形）を、別の作業として起こす（推奨のとおり）
    - 求め（ユーザー）: 3 つの選択を、経過の下のページへ移す。経過には、今の選択の要約を
      独立した押せる行として示し、押すと選択のページへ移る
    - 根拠（エージェント）: 新しいページ・場所・要約の行という新しい設計が要る。期間と
      項目の欄（TASK0006 が作った）も作り替える。TASK0035 の目的（行から気を付ける
      こととメモへ移る）と別の変更である
    - 比べた形: TASK0035 の中で続ける（第三者視点レビューを済ませた差分へ、レビューの
      無い作り替えを重ねることになる）
    - 推奨に添えた、今の形に残る点の当たる範囲が狭かった。正しい範囲（「問題」）を
      示して再判定を仰ぎ、起票を保つ裁定を受けた（2026-10-12・ユーザー）
- **選択のページから戻る方法**（2026-10-12・ユーザー）: 戻る操作だけにする（推奨の
  とおり）。選んだ時点で確定し、戻っても取り消さない
    - 根拠: 選んだ時点で確定するので、確定のボタンを置くと、戻るが取り消しに見える。
      選ぶと自動で戻る形は、1 度に 2 つを替えられない
    - 比べた形: 確定のボタンを置く・選ぶと自動で戻る
- **選択のページでの選び方**（2026-10-12・ユーザー）: 選択肢をその場に並べる（推奨の
  とおり）。期間・項目・気を付けることの見出しの下に、1 つを選ぶ一覧を置く。ページは
  縦に送れる
    - 根拠: 今の欄を 3 つ並べてダイアログで選ぶ形は、操作が 4 回になる
    - 比べた形: 欄を 3 つ並べ、押すとダイアログで選ぶ
- **要約の行の気を付けること**（2026-10-12・ユーザー）: 1 つを選んでいるときだけ示す
  （推奨のとおり）
    - 根拠: 示さないと、印が減っている理由が一覧から読めない
    - 比べた形: いつも示す・示さない
- **ページの移り方**（2026-10-12・ユーザー）: OS ごとの Material の既定に任せる（推奨の
  とおり）
    - 推奨のときに「Android の既定はスライドではない」と示したのは誤りだった。Android の
      既定も、新しいページが右から入る描き方である（「問題」の移り方の項）。任せる
      という結論は変わらない
