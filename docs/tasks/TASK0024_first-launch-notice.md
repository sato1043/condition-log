# 初めて起動したときに、このアプリについての全文を 1 度示す

## 目的

主治医に相談する旨と医療機器でない旨を、本人が設定を開かなくても一度は目にするように
する。

## 目標

- 初めて起動したときに、「このアプリについて」の全文を 1 度示す
- 閉じた後は、次からの起動で示さない。設定の「このアプリについて」からはいつでも読める
- 確かめのために、ビルドの引数（`--dart-define=RESET_ABOUT_APP_SHOWN=true`）で、起動の
  たびに「示した」を消して初回と同じに示せる

## 非目標

- 利用規約への同意を求めること（同意の画面・記録）
- 全文の文言を変えること
- 起動のたびに示すこと

## 問題

- 示したかどうかを端末に残す必要がある（設定の表へキーを足すか）。記録の書き出しと
  読み込み（TASK0010）で、このキーを移すかを決める
- 全文を示す形（ダイアログか、1 枚の画面か）と、読み上げで最初に読まれる位置
- 示している間に背景の今日のページを操作できるか
- 既に使っている端末（作者の端末）では、版を上げた後の最初の起動で示すか
- アプリ全体を起こすテスト（`pumpApp` を呼ぶ箇所が 246）は、空の DB から始まる。何も
  しなければ、すべてのテストで最初にダイアログが開き、背景を押せなくなる
- 示したことを残す書き込みが失敗すると、次の起動でもう一度示す。読み込みが失敗した
  ときに示すか示さないかで、目標のどちらを守るかが決まる

## 概要設計

- **記録**（`lib/features/settings/settings_repository.dart`）: app_settings にキー
  `about_app_shown` を足す。行があれば示した。値は `1` で、中身は読まない（行の有無だけで
  決める）。読む `aboutAppShown()` と、残す `markAboutAppShown()` を持つ。表の形は
  変わらないので、スキーマの版は上げない
- **初回の表示**（`lib/features/settings/first_launch_about.dart`）: アプリを開いた後の
  最初の描画で記録を読み、無ければ `showAboutApp` で全文を開く。ダイアログが閉じたら
  記録を残す。読めなければ報告して開き、残せなければ報告する（握りつぶさない）。
  開くのはこの部品の寿命で 1 回だけで、背景からの復帰では開かない。外枠が部品を起動の
  間保つので、画面を移っても開き直さない
- **置き場所**（`lib/app/router.dart`）: 外枠の中で、画面の群れを包む形で置く。アプリは
  常に `/` から開き、どの画面も外枠の中に出るので、開いた直後の画面によらず 1 度だけ
  働く。ダイアログは root の navigator に開き、背景（今日のページと外枠）は押せない。
  外枠そのものを包むと、外枠の組み立ての全体の字下げが変わるので、中に置く
- **起動の読み取り**（`lib/features/settings/settings_providers.dart`）: 起動のときに
  「示したか」を読む provider を置く。`RESET_ABOUT_APP_SHOWN`（`bool.fromEnvironment`）が
  真なら、読む前に行を消す。引数の無いビルドでは定数が偽で、消さない。消すかどうかは
  関数の引数で渡し、テストは両方を確かめる。読めないときは再試行しない。Riverpod の
  再試行は provider を古くするだけで、聞き手の無い provider は読み直されず、起動が
  待ち続けてダイアログを開かない
- **テスト**（`test/support/app.dart`）: `pumpApp` は既定で、起動の読み取りの provider を
  「示した」に差し替える。初回の表示を確かめるテストだけが引数で外す。テストの中で設定の
  表の行を数えるもの（`getSingle`）を崩さないため、DB に行を入れる形は採らない

## 機能への反映

### FEAT0001

外部仕様(what):
- 端末で初めてアプリを開いたときに、開いた画面の上に「このアプリについて」のダイアログを
  1 度示す。閉じ方（「閉じる」・背景・Android の戻る）によらず、閉じた後は示さない。
  閉じる前に終えると、次の起動で示す。背景から戻っただけでは示さない。示したかを読めない
  ときは示す
- 既知の課題の「初めて起動したときに示すことはまだ無い」を外す。iOS で確かめていない
  ことを既知の課題へ足す

内部設計(how):
- 示したことは設定の表のキー `about_app_shown` の行の有無で持つ。スキーマの版は上げない
- 初回の表示は外枠の中の部品 `FirstLaunchAbout` が、起動の後の最初の描画で読む。読めない
  ときは再試行せずに示す。ビルドの引数 `RESET_ABOUT_APP_SHOWN=true` で作ると、起動の
  たびに行を消す

自動化できないテスト項目:
- 初めて起動したときの全文
    - 目的: 端末で初めて開いたときに 1 度だけ全文が出るか
    - 期待結果: 最初の起動で今日のページの上にダイアログが出て、閉じた後の起動では出ない
    - 観察方法（[実機・エミュレータで確かめる](../references/device-check.md)）:
        1. `RESET_ABOUT_APP_SHOWN=true` で作ったビルドを上書きで入れて開くと出る
        2. 閉じて終え、もう一度開くとまた出る。今度は閉じずに終える
        3. 引数の無いビルドを上書きで入れて開くと出る
        4. 閉じて終え、もう一度開くと出ない
