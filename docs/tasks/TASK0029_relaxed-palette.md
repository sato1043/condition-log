# 地の色を、「リラックスするリビング」の配色から導き直す

## 目的

地の色とそこから連なる色を、雰囲気の宣言 M1（落ち着いてリラックスできる見え方）から
辿れる値にする。R1 は地の色相を指定しなくなったので、今の地の色相は M1 から導かれて
おらず、値の側にだけ残っている。

## 目標

- M1 を、引き出しの実例「リラックスするリビング」（`samples.md` の 77）へ引き当て、
  地の色をそこから導く（見え方層）
- 実装と規則が要る値だけを、新しい地の色相から導き直す。要るのは、地と地の文字・テーマが
  持つ色の役割・無効の色・部品の色・それらが指すトーンである。下限（R2・R5・R7）を
  全組で満たす（見え方層）
- 実装が使わない値と、それだけを支える規則・本文は消す。消した ID は欠番にする（見え方層）
- 部品の色の当て方を Material の既定へ寄せる。テーマの上書きは、既定では下限（R2）を
  割る箇所に限り、要らなくなった上書きと部品の表の行は消す（見え方層）
- テーマ（`lib/app/theme.dart`）とテストを新しい値へ揃える（見え方層）
- 地の色を値で名指す作業書の記述を揃える。計画の節（TASK0006）は新しい値へ改める。
  記録の節（TASK0002）は、色を値でなく役割の名前で述べ、改めたことを追記する。完了した
  作業書の到達基準と概要設計には、外した色の注記を足す（見え方層）

## 非目標

- 経過・診察の画面に地を定めること（「この記述が覆わない範囲」のまま）
- 暗い配色（ダークモード）
- 形・文字・状態の重ねの規則と値（R3・R8〜R10 と V6・V89・V90・V95〜V99 など）を変える
  こと。形を Material の既定へ寄せるのは TASK0030 が受け持つ
- 部品を足すこと

## 問題

- **引き当ての書き方**: `samples.md` は見え方記述の `vocabulary` に無い。語彙として照合
  できるのは、コードスパンの綴り（`samples.md` では HEX）と L2 見出しの最初の語だけで、
  題名「リラックスするリビング」はどちらの形でもない
- **地をどの色から取るか**: 77 の 3 色は、明るい灰 `#E2E7E3`（面積比 43.2%）・灰みの
  青緑 `#ADC2BD`（41.0%）・灰みの黄土 `#AFA67F`（15.8%）である。明るい灰は彩度がほぼ
  無く（OKLCh の C 0.008）、PCCS の色票から遠い（最も近い `p12` まで 0.055）。地を
  明るい灰にするか、青緑の淡いトーンにするかで、トーンを立てる色相が変わる
- **役割の色相の衝突**: 今の `tertiary` は青緑の 14 である。地を青緑寄りにすると、地と
  役割の距離が縮む。役割の色相を全組の距離で選び直す
- **入力欄の塗り**: R5 は、今の地がその色相でいちばん明るいトーンなので、地を白へ
  75% 寄せて入力欄を塗る。新しい地で、この例外が要るかを測り直す
- **実装が使わない値**: グラデーション（R6・V17〜V20）はコードに 0 件である。状態の色
  （`info`・`success`・`warning`。V38〜V49）は、テーマが「使う画面ができるまで外す」と
  して持たない。トーン違い（V13）の 12 トーンのうち、役割と部品が指すのは一部である。
  埋め込みのモックは値の写しで、見え方は実機の撮影で確かめる
- **テーマの上書き**: テーマは色を Material の既定から 6 つの部品で上書きしている。
  見出しの帯の面（V60）・入力欄の塗りと名前の色（R5・V86）・文字のボタンの色（V86。
  既定の `primary` が帯とダイアログの上で本文の下限を割る）・選んだ行の色・チェックの枠
  （V66）・下端のナビゲーションの面と塗りとアイコン（V91〜V94。既定の塗りが帯から
  目立たない）である。どれも今の
  配色の値に依るので、役割を既定のままで下限を満たすように選べば外せるものがある
- **候補の見比べ**: 地と役割の当て方の候補を、実機で撮って並べて裁定を受ける
- **テスト**: 色を値で確かめるテスト（`header_bar_test.dart`・`support/field.dart`）が
  ある。値を変えると落ちるので、新しい値へ直す

## 概要設計

- **引き当て**: `vocabulary` に `color | samples.md` を足し、地の値（V3）の引き当てに
  77 の HEX を点の語で書く。M1 は宣言なので `self` のまま、本文で
  「リラックスするリビング」の配色から地を取ることを述べる
- **導出の順**: 地 → 地の文字 → 面（`surfaceContainer`・`High`）→ 役割（`primary`〜
  `error`・`outline`）→ 無効 → 部品の表。各段でコントラストと OKLab の距離を測り、
  表へ書く。トーン違いの表は、最後に役割と部品が指したトーンだけを並べる
- **既定へ寄せる**: 役割を選ぶとき、Material が部品に当てる既定の役割（帯の面・文字の
  ボタン・選んだ行・チェックの枠・ナビゲーションの塗り）で下限を満たすかを測る。満たす
  部品は上書きと部品の表の行を消し、満たさない部品だけ上書きを残す
- **候補**: 少なくとも 2 つを撮る
    - A: 地を明るい灰（`#E2E7E3` に近い色）、面と役割を青緑の系統で取る
    - B: 地を青緑の淡いトーン、面を同じ色相のトーン違いで取る
    - 黄土（`#AFA67F`）は、どちらでも `secondary` の系統の候補にする
- **消すもの**: R6 と V17〜V20、V38〜V49 と R7 の状態の色の文、モックとその前置き、
  「覆わない範囲」のグラデーションの項、「引き出しの引き方」のグラデーションの測り方と
  パレットとの照合
- **コード**: `_dailyLogScheme` の 23 色と入力欄の塗りを差し替える。要らなくなった
  上書きを `dailyLogTheme` から外す。状態の色のコメントを直す。テストは、値を名指す
  ものと、外した上書きや既定の当て方を確かめるもの（8 ファイル）を直す。テーマの値と
  見え方記述の値の一致は、ID ごとに照らすテストで守る
- **作業書**: TASK0006 の 1 行を新しい V3 へ改める。TASK0002 の記録の節は色を役割の
  名前へ言い換えて追記し、TASK0002・TASK0013 の到達基準と概要設計に外した色の注記を
  足す
