# 診察の録音を文字に起こす

## 目的

診察の録音（TASK0019）を文字に起こし、聞き返さずに読み返せるようにする。

## 目標

- 診察の録音を、端末の中で文字に起こせる
- 起こした文字を、その診察に結びつけて残し、診察のページで読める
- 文字起こしの精度には限りがあることを、使う前に本人へ示し、了解を得る

## 非目標

- 起こした文字から情報を読み取り、アプリの入力（診察の欄・気を付けること・体調の記録等）へ
  反映すること
- 起こした文字の内容を解釈・要約・評価すること（憲章の非目標）
- 音声や文字を端末の外へ送って起こすこと。実行時の外部の API を使わない（憲章の非目標）
- 既存のデータを新しい持ち方へ移すこと

## 問題

- 起こす処理は端末の中で完結させる必要がある。手段は OS の音声認識か、アプリに同梱する
  認識モデルかになるが、どちらも調べていない。次の点が未確認である
    - OS の音声認識が、録音したファイルを入力に取れるか（話している最中のマイクだけで
      ないか）。端末の中だけで認識する指定が Android と iOS の両方で日本語に効くか
    - Android の OS の音声認識は Google の提供で、利用状況を送るかが分からない。送るなら
      憲章の非目標（外部へ送信しない）と食い違う
    - モデルを同梱すると、アプリの大きさがモデルの分だけ増える。日本語の精度はモデルの
      大きさに左右される
- 医療の語や薬の名前は、誤って起こされやすいと見込む（推論で、測っていない）。誤りが
  記録として残ると、後で読み返したときに医師の言葉と取り違えるおそれがある
- 長い録音を起こすと時間と電池を使う。その間に画面を離れる・アプリが背景へ移ることが
  ありうる

## 裁定記録

- **起票**（2026-10-07・ユーザー）: 診察の録音から文字起こしできるようにする。TASK0019
  とは別の作業書にする。TASK0015 のブランチで起票し、そのコミットに混ぜてよい
    - 文字起こしの精度には限りがあることを前提とし、本人にもその了解を求める
    - 起こしたテキストから情報を読み取ってアプリの入力に反映することは検討しない
- **既存のデータの移行**（2026-10-07・ユーザー）: 既存のデータを新しい持ち方へ移すことを
  非目標に置く。スキーマの版を上げる移行の段は持つ（CONTRIBUTING「開発のコマンド」）
- **既存のデータを消す**（2026-10-07・ユーザー）: 版を上げるとき、DB 全体を消し、空の DB
  から始めてよい。TASK0017・TASK0018・TASK0019 と同じ裁定である
    - 代償: 本人の端末の記録も消える
