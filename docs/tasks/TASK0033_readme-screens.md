# README に画面の画像を載せ、撮り直せるようにする

## 目的

リポジトリを見た人が、アプリを動かさなくても、どんな画面かを README で確かめられる
ようにする。画面が変わっても、同じ見本の記録で 1 コマンドで撮り直せるようにする。

## 目標

- README に、アプリのすべてのページの画像を載せる。中身がまだ無いページも、今の表示を
  載せる
- 今日のページは、最初の画面に収まらない終わり（気を付けることのチェックとメモ）も載せる
- 各ページを、OS の文字の大きさが既定のときと最大のときの 2 枚で並べる（憲章の目標
  「最大サイズでも表示を崩さない」を見せる）
- 画像に写る記録を、架空の見本に限る
- 見本の記録を、手で打たずにアプリへ入れる仕組みを持つ
- 見本を入れる・画面を辿る・撮る・リポジトリへ置くまでを、1 コマンドで行える
- 配布するアプリ（`lib/main.dart` から始まるビルド）に、見本の仕組みを含めない

## 非目標

- 配布するアプリの振る舞いと見た目を変えない
- ダイアログ・メニュー・過去の日のページ・初めての起動の全文を撮らない（ページに限る）
- 暗い配色・横向き・iOS の画面を撮らない
- エミュレータで撮らない。既定の文字も最大の文字も、テスト用の端末（SM-A253C）で撮る
- テスト用の端末の設定を、撮った後に変えたままにしない
- ストアに載せる画像を作らない（公開の段で扱う）
- 画像の差を機械で比べて、見た目の変化を検査しない（golden のテストにしない）
- 画面を変えた作業で撮り直すことを、機械で求めない。作業ごとの撮り直しを規則にも
  しない（節目でまとめて撮り直す）

## 問題

見本を入れる経路:

- adb の `input text` は日本語を打てない（既知の制約。この環境では試していない）。メモ・
  気を付けることの名前・受診先の名前・診察の欄は、外から打てない
- テスト用の端末は市販の端末で、root を取れない。アプリの領域へ DB のファイルを外から
  置けない。エミュレータ（`MediumPhone`）も Play Store 版のイメージで、同じである
  （`config.ini` の `tag.id=google_apis_playstore`）
- アプリの領域へ `run-as` で置けるのは debug のビルドだけで、debug のビルドは右上に
  帯が出る（`debugShowCheckedModeBanner` を切る行は `lib/` に 0 件）
- ビルドの引数で振る舞いを変える先例がある（TASK0024 の `RESET_ABOUT_APP_SHOWN`）。
  この形は、見本のコードが配布するアプリのソースから辿れる

撮る画面:

- ページは 7 つある（`lib/app/router.dart`）。今日のページ・気を付けることの編集・設定・
  経過・診察の一覧・診察のページ・受診先である。経過は中身がまだ無く、準備中の表示を
  出す（`TrendReviewPage`）
- 外のリンクから画面を開けない（TASK0002 の規則）。ページへは、画面を押して辿る
- 今日のページの見出しに今日の日付が出る。固定しないと、撮る日ごとに画像が変わる。
  時計を読むのは `clockProvider` の 1 か所である（`lib/` の `DateTime.now` は
  `lib/ui/today.dart` だけ）
- テスト用の端末の文字の倍率は 2.0 にしてある。倍率は adb で変えられる（2026-10-10 に
  試した）。`settings put system font_scale 1.0` の後、画面の構成の倍率が 1.0 になり、
  2.0 を入れ直すと戻った。Samsung の設定が別に持つ値（`device_font_scale`）は 1.0 の
  まま動かなかった。設定の画面の表示がずれるかは見ていない
- OS の状態の帯（時刻・電池・通知・通信の印）が写る。SystemUI のデモモードは、この
  端末では効かない（2026-10-10 に 2 回試した。時刻も印も変わらなかった）。時刻が写る
  限り、撮るたびに画像が変わる
- テスト用の端末の幅は 384 dp（720 x 1600 px・密度 300）で、作業書が仮定する 360 dp
  より広い。画像は見え方の例で、対応する範囲（TASK0011）の確かめではない
- 画面は文言で見分ける（[実機・エミュレータで確かめる](../references/device-check.md)
  「守ること」）。ARB の文言を変えると、道具は画面を見つけられずに止まる

画像を置くこと:

- 画像は、書き換えても前の版が履歴に残る。`main` を書き換えない運用なので、撮り直す
  たびに積み上がる。画面が変わらなければ同じバイト列になる撮り方なら、変わった画面の
  分だけが積まれる。OS の帯を隠した見本のビルドでは、撮り直した画像がすべて同じ
  バイト列になった（作業記録 2026-10-10）
- 画像 1 枚は 720 x 1600 px で、16 枚の合計は約 1.45 MB である（1 枚 30〜193 KB。
  2026-10-10 に測った）
- 今日のページは TASK0026・TASK0017・TASK0028・TASK0031 が変え、経過は TASK0006 が
  中身を作る。撮り直しが続く
- 見本のビルドは、通常のビルドと同じ ID のアプリとして上書きで入る。端末の記録の
  ファイルは残るが、見本のビルドの間は見えない。道具を本人の記録が入った端末へ向けても
  同じことが起きる

## 概要設計

- **見本の入口**: `lib/sample/sample_main.dart` に、もう 1 つの `main` を置く。
  `flutter build apk --release -t lib/sample/sample_main.dart` で作る。通常の入口と
  同じ `ConditionLogApp` を、2 つを差し替えて起動する
    - DB: `appDatabaseProvider` を、メモリの DB（`NativeDatabase.memory()`）へ
      差し替える。起動のたびに見本を入れ直すので、いつ撮っても同じ状態から始まる。
      端末の記録のファイルには触れない
    - 時計: `clockProvider` を固定の日時（2026-10-07 09:00）へ差し替える。今日の
      ページの日付と、診察の「これから」「受けた」の区分が、撮る日に依らなくなる
    - OS の帯: 状態の帯と下のボタンの帯を隠して起動する
      （`SystemUiMode.immersiveSticky`）。時刻と通知の印が写らず、撮り直した画像が同じ
      バイト列になる。比べた案は、SystemUI のデモモード（テスト用の端末で効かない）・
      撮った後に切り取る（画像を加工する依存と手順が増える）・そのまま載せる（撮る
      たびに全部の画像が変わる）
    - 比べた案: ビルドの引数（`--dart-define`）で通常の入口の中を分ける形。先例
      （TASK0024）に揃うが、見本のコードが `lib/main.dart` から辿れ、配布するアプリに
      含まれないことをコンパイラの最適化に頼る。入口を分ければ、import が無いことを
      テストで確かめられる
    - 比べた案: テストのコードで DB のファイルを作り、端末へ置く形。端末で root を
      取れず、debug のビルドは帯が出る（問題）
- **見本の記録**: `lib/sample/sample_records.dart` が、記録のポートを通して入れる。
  スキーマや検証が変わると、コンパイルかテストが落ちて気づける
    - 気を付けること 3 件・今日を含む 14 日分の体調（今日はメモと気を付けることの
      印つき）・受診先 2 件（1 件をいつもの受診先にする）・受けた診察 2 件と、これからの
      診察 1 件
    - 初めての起動の全文は「示した」にして、出さない
    - 名前と文は架空のものにし、受診先は「みほん」を冠して実在の名前と紛れなくする。
      文言は、撮った画像で裁定を受けた（裁定記録「画像の内容」）
- **撮る道具**: `tool/capture_screens.dart` を、端末の ID を渡して `dart run` で回す。
  Dart で書き、パッケージを足さない。adb を直接呼ぶので、シェルのパスの書き換えを
  受けない
    1. 端末の ID を引数で受け取る。渡されなければ止まる。撮る前の文字の倍率を読んで
       控える
    2. 見本の入口でビルドし、上書きで入れる（`--no-build` でビルドを飛ばせる）
    3. 文字の倍率を 1.0 にして起動し、7 ページを順に辿って撮る。2.0 でもう 1 度行う
    4. 文字の倍率を控えた値へ戻す（失敗したとき・Ctrl-C で止めたときも）
    - 辿り方は、意味の木（`uiautomator dump`）から文言で部品を探し、その中心を押す。
      押すたびに、着いた画面の文言を確かめてから撮る
    - 起動のたびに、見本の日付が出るのを待つ。見本でないビルドを撮らない
    - 今日のページは、最初の画面と、送りが止まる終わりの 2 か所で撮る。終わりは毎回
      同じ位置になる。送った後、最初の画面に無い「編集」が見えてから撮る
    - 画像は、続けて撮った 2 枚が同じになってから保存する。移り変わりの途中を撮らない
    - 画像は `docs/images/screens/<ページ>-default.png`・`<ページ>-largest.png` に置く。
      今日のページの終わりは `daily-log-end` の名前にする
    - 意味の木から部品を探して中心を返す部分は、端末を要さない関数に分け、端末から
      取った意味の木の断片でテストする
- **README**: 「主な機能」の後に「画面」の節を足す。ページごとに 1 行（今日のページは
  最初の画面と終わりの 2 行）、既定と最大の 2 列の表で、画像は幅を指定して縮めて
  見せる。経過の行には、準備中の表示であることを添える
- **手順のドキュメント**: device-check.md に「README の画面を撮り直す」の節を足す。
  見本のビルドが通常のビルドを上書きすること、撮り終えたら通常のビルドを入れ直すこと、
  本人の記録が入った端末へ向けないことを書く。TASK0012 の問題へ、配布のビルドを
  `lib/main.dart` から作ることを 1 行足す
- **CONTRIBUTING**: `dart format` と確かめのコマンドの範囲へ `tool` を足す
- **画像の大きさ**: 撮ったままの大きさで置き、縮めない。16 枚で約 1.45 MB で、撮り
  直しても変わったページの分しか履歴に積まれない（エージェントの判断。裁定記録）

### CP6 の提案の根拠
