# 毎日の体調を記録する

## 目的

体調が悪い日でも、開いてタップするだけで 1 日分の体調を残せるようにする。途切れずに
残った記録が、後の振り返りと診察の材料になる。

## 目標

- 開いてタップするだけで 1 日分の記録を終えられる（SREQ0001）
- 1 日 1 ページで体調を記録でき、未入力の項目があっても保存できる（SREQ0001）
- 全体の体調を 5 段階で記録できる（SREQ0001）
- 痛み・だるさ・睡眠・食欲・気分を、それぞれ 5 段階で記録できる（SREQ0001）
- 気を付けること（この作業では、間食・入浴・運動など控える行動だけを扱う）を本人が
  登録し、その行動をした日にチェックできる（SREQ0002）
- 出来事や体調の変化を自由記述のメモで残せる（SREQ0001）

## 非目標

- 家族による代理入力を、別の利用者として扱わない
- DB を暗号化しない。アプリのロックとタスク切り替え画面の見え方も扱わない（TASK0009 が
  持つ）
- 記録の書き出しと読み込みを扱わない（TASK0010 が持つ）
- 未来の日のページを開かない
- 1 日の記録を時刻ごとに分けて持たない。その日のうちの変化はメモに書く
- 対応する端末の範囲を決めない（TASK0011 が持つ）。本作業は、画面を 360 x 640 dp、
  文字の最大を Android 2.0 倍・iOS の AX5 と仮定して確かめる

## 問題

- 体調が悪い日ほど記録は続かない
- 起動から当日の記録ページを開くまでの待ち時間も、タップ数と同じ負担になる
- 記録が失われる経路は端末の紛失だけでない。保存中のアプリの終了と、DB のスキーマの
  変更（後の作業も表を足す）がある
- Android 11 以下（API 24〜30）は、クラウドへのバックアップと端末間の移行を別々に
  除外できない。`minSdk` は Flutter の既定の 24 である
- 生成されるローカライズのコード（`flutter gen-l10n`）が、framework 内の
  `GlobalMaterialLocalizations` を指す可能性がある。`material_ui` の型と食い違うかは、
  基盤を入れる段で確かめる

## 概要設計

### 構成

機能単位でフォルダを分け、共通化は必要になってから行う。

```
lib/
  main.dart
  app/            MaterialApp.router・ルーティング・テーマ・注意書きの外枠・
                  ポートと drift 実装の結線（composition.dart）
  data/           drift の DB と表の定義・DB の開き方・値を落とした失敗の報告
  domain/         機能をまたぐ値（区切り時刻 DayStartHour）
  ui/             画面をまたぐ部品（読み込みの失敗・保存の失敗の知らせ・入力欄の飾りと
                  補足・VoiceOver で読むかの判定）
  features/
    daily_log/
      domain/     記録・暦の日付・段・気を付けること・リポジトリの抽象（ポート）
      data/       リポジトリの drift 実装
      ui/         今日のページ・段の選択部品と段の語・気を付けることの編集・
                  状態（Riverpod）・文字に添えるアイコンの大きさ
    settings/     区切り時刻の設定
  l10n/           ARB と生成コード
```

- 依存の向きは `ui` → `domain` ← `data` とする。`domain` は Flutter にも drift にも
  依存しない。ポートと drift 実装を結ぶのは `app` だけで、`ui` は drift 実装を知らない。
  向きは `test/app/layering_test.dart` が確かめる
- 設定のリポジトリはポートと実装に分けない（裁定記録「CP6 の指摘の扱い」）
- 状態管理は Riverpod（`Notifier` / `AsyncNotifier`。コード生成は使わない）、
  ルーティングは go_router を使う。どちらも依存に入っている

### ドメイン

- **暦の日付**（`CalendarDay`）: 年月日だけを持つ値。DB には `YYYY-MM-DD` の文字列で
  置く。時刻もタイムゾーンも持たないので、タイムゾーンを変えても記録は動かない
- **「今日」の規則**: 端末のローカル時刻から区切り時刻を引いた時点の日付を「今日」と
  する。区切り時刻は 0〜23 時で、既定は 0 時。区切り時刻は、画面の文言では「日付が
  変わる時刻」、コードでは `DayStartHour` と呼ぶ
    - 2026-10-01 03:59・区切り 4 時 → 2026-09-30
    - 2026-10-01 04:00・区切り 4 時 → 2026-10-01
    - 2026-10-01 00:00・区切り 0 時 → 2026-10-01
- **段**（`Score`）: 1〜5 の値。5 が良い側である。未入力は段を持たない（`null`）
- **1 日分の記録**（`DailyLog`）: 日付・全体・痛み・だるさ・睡眠・食欲・気分・メモ。
  日付以外はすべて任意
- **気を付けること**（`Avoidance`）: 名前・並び順・使っているか。使わなくした項目は
  一覧から外れるが、過去のチェックは残す

### 永続化（drift・スキーマ版 1）

| 表 | 列 | 備考 |
|---|---|---|
| `daily_logs` | `day` TEXT 主キー（`YYYY-MM-DD` の CHECK）、`overall`・`pain`・`fatigue`・`sleep`・`appetite`・`mood` INTEGER NULL（1〜5 の CHECK）、`memo` TEXT NULL、`updated_at` INTEGER | 1 日 1 行。`updated_at` は書いた時刻で、読む箇所は無い |
| `avoidances` | `id` INTEGER 主キー、`name` TEXT、`sort_order` INTEGER、`in_use` INTEGER（0・1 の CHECK） | |
| `avoidance_checks` | `day` TEXT（`YYYY-MM-DD` の CHECK）、`avoidance_id` INTEGER（外部キー）、主キーは 2 列の組 | 行が在ることを「した」とする |
| `app_settings` | `key` TEXT 主キー、`value` TEXT | 区切り時刻を置く |

- DB ファイルはアプリの領域（`getApplicationSupportDirectory`）の下の専用のディレクトリ
  （`records/`）に置く。iOS ではこの領域が既定でバックアップに載り、除外はファイルか
  ディレクトリの単位で付ける。ディレクトリに付ければ、SQLite が隣に作るファイルも外れる
- 日付の列の CHECK は `GLOB` で形（ASCII の数字）を確かめる。`CalendarDay` を通らずに
  書く経路（TASK0010 の読み込み）で別の形が入ると、その日の記録を引けなくなる
- ジャーナルモードと `synchronous` は SQLite の既定のままにする。書き込みは 1 タップに
  1 回で少なく、耐久性を優先する既定が「記録を失わない」に合う。書き込みが増える
  作業で WAL へ移すかを見直す
- 段を選ぶたびに 1 行を upsert する。1 回の書き込みは 1 トランザクションに収める
- スキーマは `drift_dev` の `make-migrations` で版 1 を書き出し、移行のテストを生成できる
  状態にする。後の作業が表を足すときは版を上げ、そのテストで確かめる
- sqlite3 3.x は build hook で SQLite を同梱するので、`sqlite3_flutter_libs` を外す

### 画面

```
┌──────────────────────────────────────┐
│ 体調記録                         ⚙    │ アプリのヘッダー（記録と流れる）
│ ◀     10月1日（水）  今日         ▶   │ 日付の帯（流れずに残る）
├──────────────────────────────────────┤
│ この日全体をふり返って                │ 一覧の先頭（記録と流れる）
│ 全体の体調                           │
│ [悪い] [ ・ ] [普通] [ ・ ] [■良い]   │
├──────────────────────────────────────┤
│ 痛み                                 │
│ [強い] [ ・ ] [軽い] [ ・ ] [無い]    │
│ だるさ（元気が出ない）・睡眠・食欲・ │
│ 気分（不安・落ち込み）               │
├──────────────────────────────────────┤
│ 気を付けること            [✎ 編集] │
│ ☐ 間食   ☐ 入浴   ☐ 運動              │
├──────────────────────────────────────┤
│ ┌メモ─────────────────────────────┐ │
│ └─────────────────────────────────┘ │
│ よい出来事・悪い出来事や…            │ 欄の下の補足
├──────────────────────────────────────┤
│ ⓘ 医療上の判断は主治医にご相談ください │ 外枠（全画面共通）
└──────────────────────────────────────┘
```

- 段の語は尺度ごとに 5 つ持ち、ARB に置く。キーも尺度ごとに分け、日本語で同じ語
  （食欲の「無い」・「普通」）も別のキーにする

  | 尺度 | 1 | 2 | 3 | 4 | 5 |
  |---|---|---|---|---|---|
  | 全体の体調・睡眠・気分 | 悪い | やや悪い | 普通 | やや良い | 良い |
  | 痛み・だるさ | 強い | 中くらい | 軽い | わずか | 無い |
  | 食欲 | 無い | 少ない | 普通 | ややある | ある |

- 1・3・5 段目のボタンに語を、2・4 段目のボタンに「・」を書く。段の下には何も
  置かない。ボタンの内側に余白を取らず、語を中央に揃える。文字は OS の大きさのまま縮めず
  （見え方記述 R3）、ボタンに入らない分は省略記号で省く。選んだ段は塗りで示し、✓ などの
  印は足さない。印を語の上に積むと、大きい文字で段が 24 dp ずつ高くなる
- 段の選択部品は 5 つのラジオボタンの組にし、各段へ読み上げ名「項目、段の語」を
  持たせる（例:「痛み、中くらい」）。選んだ状態は塗りで示す
- 選んだ段は、もう一度押すと未入力に戻る。ラジオボタンの慣習から外れるので、読み上げ
  では「選択を解除」と補う
- iOS の VoiceOver は、ラジオの組の選んだ状態と押す動作の案内を読まない（engine の
  ソース）。iOS では、Flutter のラジオボタンと同じく、選んだ段に選択の状態を、選んで
  いない段に「選択されていません」を、選んだ段に「選択を解除」を案内として添える
- 項目名と「気を付けること」は見出しとして読み上げる。VoiceOver は見出しの段を持たないと
  見出しと読まないので、日付を段 1、項目名と「気を付けること」を段 2 にする
- 「今日」のページでは ▶ を押せない状態にする。過去の日のページでは、見出しの「今日」の
  位置に「今日へ」のボタンを出す（見出しの幅を変えない）
- ◀▶ と設定のアイコンは、OS の文字の大きさに合わせて 1.5 倍（36 dp）まで拡げる。この
  大きさなら、最大の文字サイズでも日付の行数が変わらず、どの画面もはみ出さない（テストの
  フォントで測った）
- 気を付けることの欄は、見出しの下に「した日にチェックします」と添える（登録がある日
  だけ）。チェックは、控える行動をした日に付ける
- 記録の一覧の先頭に「この日全体をふり返って」を本文の大きさで置く。日付の帯は
  流れずに残るので、帯の中でなく一覧の先頭に置き、記録の欄を狭めない
- だるさと気分の見出しは「だるさ（元気が出ない）」「気分（不安・落ち込み）」とし、括弧の
  定義を補足の大きさにして名前と同じ行に収める。定義は見出しにだけ添え、段の読み上げ名には
  入れない。項目の語に定義を持たせ、定義の無い項目は名前だけを出す
- メモの欄の下に、補足の大きさで「よい出来事・悪い出来事や、何時ごろ具合が変わったかを
  書いておくと、振り返りに役立ちます」と添える。入力の後も消えない
- 欄の下の補足は、読み上げでは欄の案内（hint）として欄と一緒に読み、欄の後の別の文と
  しては読まない。打ち始める前に聞けるようにするためである。補足は欄の外に置き、欄を
  押せる範囲と押した表示を枠に限る。左端は欄の中の文字に揃える
- 入力欄は地を白へ寄せた色（V85）で塗って枠を付け、欄の名前を何も書いていない間も
  枠の上辺に置く。地と同じ色の内側と、枠の中央に座る名前は、中身の無いカードの枠や
  ボタンに見えるため。白そのものは淡い地の上で際立ちすぎるので、地を 25% 残す
    - TASK0029 で入力欄を塗らずに枠で示す形へ改めた（V85 は欠番）
- 上辺の名前は、Material が 0.75 倍に縮めるので、本文の大きさに OS の文字の大きさを
  当てた値の 1/0.75 倍で組み、OS の拡大はそれ以上当てない。Android 14 以降は大きい文字
  ほど拡大を抑えるので、文字の大きさを 1/0.75 倍にするだけでは本文より小さく出る
  （同じ形の拡大をテストで当てて確かめた。実機の拡大の表そのものでは測っていない）
    - TASK0030 で、名前を Material の既定の大きさで描く形へ改めた
- 上辺の名前は 1 行に収め、入らない分は段の語と同じく省略記号で省く（読み上げは全文）。
  2 行に折れると枠をまたいで欄の中へ入る
- 欄の中身の上の余白は、上辺の名前の大きさに合わせて拡げる。Material は文字の大きさに

### 外枠・テーマ・ローカライズ

- 全画面の下端の注意書きは、router の `ShellRoute` が画面を包む外枠に置く。外枠は
  最上位の Navigator の下にあるので、ダイアログとメニューは外枠ごと覆う。文字サイズに

  往復しないため）。スクリーンリーダーを使っている間は隠さない（読み上げの順で帯に届く

  スクロールは聞かない。隠した間も、OS のナビゲーションの帯の分の余白は残す。出し入れは

### バックアップの構成（Android）

- `android:dataExtractionRules`（API 31 以上）: `cloud-backup` ですべての領域を除外し、

## 機能への反映

### FEAT0001

外部仕様(what):
- 起動すると「今日」のページが開き、全体の体調と 5 項目（痛み・だるさ・睡眠・食欲・
  気分）を、5 段のボタンから 1 タップずつ選べる。選んだ段をもう一度押すと未入力に戻る
- 段に数字は出さず、1・3・5 段目のボタンに語を、2・4 段目に「・」を出す。全項目で
  右が良い側である。選んだ段は塗りで示す。読み上げでは段をラジオボタンとして「項目、
  段の語」（例:「痛み、中くらい」）で読む。文字は OS の大きさのまま縮めず、ボタンに
  入らない語は省略記号で省く
- 選ぶたびに保存し、保存の操作は無い。入力はすべて任意である。保存に失敗したら画面の
  下にその旨を示し、段は保存済みの値へ戻る。メモは欄に文を残し、後で自動で保存し直す。
  読み込みに失敗したら、その旨と「読み込み直す」を示す
- 本人が登録した気を付けること（控える行動）を、その行動をした日にチェックできる。欄の
  見出しの下に、チェックはした日に付けると示す。気を付けることは別の画面で登録・名前の
  変更・並べ替え・使わなくすることができ、各行のメニューから選ぶ（並べ替えはドラッグ
  でもできる）。使わなくした直後は、知らせから元の位置へ戻せる。後から使う側へ戻した
  項目は末尾に入る。使わなくした項目も、チェックした過去の日のページには残る
- 段は、その日全体をならした体調を表す。記録の先頭に「この日全体をふり返って」と示す。
  1 日の記録を時刻ごとに分けず、その日のうちの出来事や変化はメモに書く
- だるさの見出しに定義「元気が出ない」を、気分の見出しに定義「不安・落ち込み」を、補足の
  大きさで添える。段の読み上げ名には入れない
- 自由メモを残せる。入力が止まったとき・欄を離れたとき・アプリが背景へ移るときに保存する。
  欄の下に、よい・悪い出来事や、何時ごろ具合が変わったかを書くとよいと示す
- ◀▶ で過去の日を開いて書き足せる。過去の日からは「今日へ」で 1 回で戻れる。「今日」
  より先の日は開かず、時計やタイムゾーンが戻っても今日へ寄せる。「今日」のページを
  開いている間に日が変わると、新しい「今日」へ移る（区切り時刻に、またはアプリを背景から
  戻したとき）
- ◀▶ と設定のアイコンは、OS の文字の大きさに合わせて 36 dp まで拡がる
- 「今日」を決める区切り時刻を、設定の画面で 0〜23 時から選べる。既定は 0 時である。
  設定の画面は、今日のページの最上段のアプリのヘッダーの歯車から開く。ヘッダーは記録と
  一緒に流れて消え、ページの先頭へ戻すと現れる
- 全画面の下端に、医療上の判断は主治医に相談する旨を示す。アプリを開いたとき（背景からの
  復帰を含む）と画面を移ったときに見え、送れる長さが残る画面を先頭から下へ送ると隠れ、
  先頭へ戻すと現れる。スクリーンリーダーを使っている間は隠さない。帯を押すと、題名
  「このアプリについて」のダイアログで全文を示す。全文は、診断・治療・予防に使うことを
  目的とせず医療機器ではない旨を含む
- 欄の下の補足（メモの書き方・区切り時刻の説明）は、読み上げでは欄と一緒に案内として読む
- iOS の VoiceOver でも、段の選んだ状態と解除の案内、見出しが伝わるように、iOS のときだけ
  読み上げの情報を足す（Mac での確かめは残課題）

内部設計(how):
- ビジネスロジック層: 暦の日付・「今日」の規則（ローカル時刻から区切り時刻を引いた
  時点の日付）・段（1〜5、5 = 良い、未入力は値なし）・1 日分の記録・気を付けること

  チェックは行の有無で表す。使わなくした気を付けることは一覧から外し、過去のチェックは残す
- 永続化は端末内の SQLite（drift。スキーマ版 1）で、記録は暦の日付の文字列をキーに持つ。
  区切り時刻も同じ DB に置き、読めない値は 0 時として扱う
- Android 12 以上はクラウドへのバックアップからアプリの全領域を除き、端末間の移行には
  含める。Android 11 以下はどちらからも除く
