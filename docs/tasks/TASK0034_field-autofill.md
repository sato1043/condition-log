# 入力欄の内容を、OS の自動入力へ渡すかを決める

## 目的

本人が入力欄へ書いた記録（気を付けることの名前・メモ・診察の欄・受診先の名前）が、
本人の知らないうちに OS の自動入力（Autofill）のサービスへ渡らないようにするかを決め、
決めた形に揃える。記録は要配慮個人情報にあたる（要求一覧「プロジェクト憲章」）。

## 目標

- 入力欄の内容を OS の自動入力へ渡すか渡さないかを、アプリの全部の入力欄で 1 つに
  決める
- 決めた形を、全部の入力欄に当て、入力欄を足したときに漏れない形で守る

## 非目標

- キーボードの学習を止める指定を変えること（TASK0014 が入れた。そのままにする）
- 本人の操作で記録を端末の外へ出す経路（書き出し。TASK0010）
- OS のバックアップの扱い（FEAT0001 の内部設計に在る形のままにする）

## 問題

- Flutter の `TextField` は、`autofillHints` の既定が空のリストである（Flutter 3.47.5 の
  `material/text_field.dart` で読んだ）。空のリストは「無し」ではなく、指定が null で
  ないかぎり、欄は自動入力の対象になる。Android では、欄へフォーカスしたときと文字が
  変わるたびに、欄の今の文字が自動入力の仕組みへ知らされる（TASK0026 の第三者視点
  レビューが、Flutter と engine のソースを読んで指摘した）
- アプリの入力欄は 3 つの部品に在る。気を付けることの名前
  （`lib/features/daily_log/ui/precaution_name_field.dart`）・メモと診察の欄
  （`lib/ui/note_field.dart`）・受診先の名前
  （`lib/features/visits/ui/care_provider_names.dart`）である。どれも `autofillHints` を
  指定していない（2026-10-10 に `lib` を引いて 0 件）
- 端末で自動入力のサービスへ実際に届くかは、確かめていない。届くかは端末の設定
  （自動入力のサービスを選んでいるか）に依り、サービスが何を保存して同期するかは
  サービスに依る
- アプリが送信するのではないが、OS の側の部品が記録を端末の外へ持ち出しうる。憲章は、
  OS が記録を端末の外へ出しうる経路を、扱う作業書で非目標と照らすと定める。同じ族の
  経路であるキーボードの学習には、指定とテストが在る。自動入力には、守りも記録も無い
- 欄の指定を null にすると、Android と web でその欄の自動入力が無効になる（Flutter の
  ドキュメントコメント）。iOS での扱いは確かめていない（Mac で作業するとき）
- 自動入力を止めると、本人が自動入力で名前を入れる使い方はできなくなる。記録の欄で
  それを使う場面があるかを見てから決める
