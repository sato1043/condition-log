# 体調の推移を振り返る

## 目的

体調の変化を自分で振り返り、気づけるようにする。気を付けることができた日と体調の
関係も確かめられるようにする。

## 目標

- 体調の推移を日を追って確かめられる（SREQ0007）
- 気を付けることができた日に、その名前をその日の行へ重ねて示す（SREQ0008）
- 診察日を軸に読める。期間に「前回の診察から」を持ち、一覧に診察日の区切りを挟む
- メモのある日に印を付け、行からその日の記録のページを開ける
- 経過の画面の地と一覧の色を、見え方記述に宣言する（見え方層）

## 非目標

- 気を付けることの登録と印を扱わない（TASK0026 が持つ）
- 診察の記録の入力と表を扱わない（TASK0014 が持つ）。区切りの行から診察のページを
  開かない
- 診察日以外の節目（薬が変わった日など）を区切りにしない
- 推移や比較を「改善」「悪化」「変化なし」と判定しない。矢印・差の数値・平均・傾向線・
  良し悪しを示す色を出さない（憲章の非目標）
- 日と日を線でつながない。記録の無い日の値を補わない
- 一覧の行から記録を書き換えない。書き換えは日のページ（今日のページと同じ部品）が持つ
- DB の表を変えない。スキーマの版を上げない（版 2 は TASK0014 が作る）
- 下端のナビゲーション（外枠）の振る舞いを変えない

## 問題

- 推移の元データは TASK0002 の記録の表（`daily_logs`・`precaution_marks`）とその
  ポートである（`depends-on`）
- 診察日は TASK0014 の表とポートから読む（`depends-on`）。本作業が使う読み出しは、
  期間の中の診察日と、今日より前の最も新しい診察日の 2 つである。TASK0014 のポート
  `VisitRepository` が、この 2 つを `visitDaysBetween(first, last)`（両端を含み、日で
  まとめて古い順）と `lastVisitDayBefore(day)`（その日を含まない）として持つ
- 1 日に 2 回以上の診察は TASK0014 で許すと裁定された。`visitDaysBetween` は日でまとめて
  返すので、本作業は日ごとに区切りを 1 つ出せばよい
- 今日のページの日の部品の「この日全体をふり返って」の行に、TASK0014 が診察のボタン
  （`DayVisitButton`）を置いた。ボタンは今日の記録の行き先から押すことを前提に、1 件の日は
  診察のページを上へ重ね、2 件以上の日は診察の行き先へ移る。日のページで部品を共有すると、
  経過の行き先からも同じ動きになる（TASK0014 の CP6 から）
- 診察日の 2 つの読み出しは Future だけで、変化を知らせない。経過の画面は隠れている間も
  残るので、診察の行き先で日付を変えても、本作業の読み直す契機（期間・今日・日のページ
  からの帰り）のどれにも当たらない（TASK0014 の CP6 から）
- 経過の行き先・ルート `/review`・`TrendReviewPage`・`Destination.review` は TASK0013 が
  作った。今は準備中の 1 文だけを出す
- 訪れた行き先の画面は、隠れている間も `Offstage` の下でレイアウトされる。下端の
  ナビゲーションの高さが変わる各フレームで、経過の画面も作り直される（TASK0013 の
  概要設計。測っていない）
- 経過の先頭の画面で戻る操作をすると、今日の記録へ移る。今日の記録で戻る操作をすると
  アプリが閉じる（TASK0013）。日のページを今日の行き先で開くと、戻る操作で一覧へ帰れない
- 今日のページが出す日（`shownDayProvider`）はアプリに 1 つで、今日の記録の行き先が
  持つ。経過から別の日を開くためにこれを動かすと、今日のページの日も動く
- 段は 1〜5 の順序の尺度で、間隔の等しさは保証されない。線の傾きや平均は、段の差を量と
  して読ませる
- 推移の表示は、アプリが評価を出したと受け取られうる場面である（記録
  `20261003_consult-doctor-notice-basis.md` の推論）。本作業は判定を出さないことで
  これを避ける。主治医に相談する旨は、設定の「このアプリについて」が持つ（TASK0023）
- 「前回の診察から」の期間には上限が無い。診察の間が 3 か月なら約 90 行になる
- 依存の `fl_chart` は本作業のために入れたが、一覧の形ではグラフの部品が要らないので、
  本作業の前に外した
- 見え方記述は、経過の画面の地の色を「覆わない範囲」に置いている。TASK0013 は R1 を
  広げず、毎日の記録の画面の役割で描いた

## 概要設計

### 構成

```
lib/
  features/
    daily_log/
      domain/     CalendarDay へ日数の加減を足す。ポートへ期間で引く操作を足す
      data/       drift 実装へ期間の読み出しを足す
      ui/         日の記録の部品を、今日のページと日のページで共有する形にする
    trend_review/
      domain/     期間・一覧の行（段・添え書き・気を付けること・メモ・区切り）
      ui/         経過の画面・行の部品・日のページ・状態（Riverpod）
  app/            ルーティングへ日のページ（/review/day/:date）を足す
  l10n/           ARB へ文言を足し、準備中の文を外す
```

- 経過は記録の別の見方であり、記録を持つ機能（FEAT0001）とも行き来（FEAT0002）とも
  別の新しい機能にする。番号は導出（spec-derive）のときに採る（作業記録）。
  記録の表とポートは FEAT0001 のものを読み、診察日は TASK0014 が作る機能のポートから読む
- 依存の向きは TASK0002 と同じく `ui` → `domain` ← `data`。`trend_review/ui` は
  `daily_log/domain` のポートと `daily_log/ui` の段の語（`conditionLabels`）を使う。
  段の語を共通の場所へ移すのは、使う画面が 3 つ目になってからにする
- 経過の画面は TASK0013 の `TrendReviewPage` の中身を差し替える。ルートと識別子は
  変えない

### ドメイン

- **日数の加減**: `CalendarDay.plusDays(int)`。UTC の日付で足すので、夏時間で日が
  ずれない
- **期間**（`TrendPeriod`）: 前回の診察から・1 週間・2 週間・4 週間。今日と期間（と
  前回の診察日）から、最初の日〜今日の日の並びを作る
- **前回の診察日**: 今日より前（今日を含まない）の最も新しい診察日。診察日の当日に
  開いても、その前の診察からの経過が見える
- **一覧の行**: 日ごとに、選んだ項目の段（または記録なし）・添え書き（今日の行の
  「今日」）・印を付けた気を付けることの名前・メモの有無を持つ。診察日の行の前に区切りの
  行を置く

### 読み出し

- `DailyLogRepository.logsBetween(first, last)`: 期間の記録のある日の `DailyLog` を
  日付の順で返す。`day` は `YYYY-MM-DD` の文字列で、文字列の比較が日付の順に一致する
  ので `BETWEEN` で引く
- `PrecautionRepository.marksBetween(first, last)`: 期間の日ごとの印を返す。名前は
  使っている・使っていない気を付けることの一覧から引く
- 診察日は TASK0014 のポートから、期間の中の診察日と前回の診察日を引く
- 読み出しは Riverpod の provider が持ち、画面の build では読まない。読み直すのは、
  期間を変えたとき・今日が変わったとき・日のページから帰ったときだけである。外枠の
  出し入れで画面が作り直されても、provider は読み直さない

### 画面

```
┌──────────────────────────────────────┐
│ 経過                                  │
├──────────────────────────────────────┤
│ (■前回の診察から) (1週間) (2週間)       │ 期間（1 つを選ぶ。折り返す）
│ (4週間)                                │
│ (■全体の体調) (痛み) (だるさ)           │ 項目（1 つを選ぶ。折り返す）
│ (睡眠) (食欲) (気分)                   │
├──────────────────────────────────────┤
│ ── 診察 9月26日 ─────────────────── │ 区切りの行
│ 9/26 土          □ ■ □ □ □      ›  │
│ 9/27 日          □ □ ■ □ □  ✎   ›  │ ✎ はメモの印
│        入浴                           │ 気を付けることの名前
│ 9/28 月 未記録    □ □ □ □ □      ›  │
│ …                                     │
│ 9/30 水          □ □ □ ■ □      ›  │
│ …                                     │
│ 10/4 日 今日      □ □ ■ □ □  ✎   ›  │ 開いたときに見える
└──────────────────────────────────────┘
```

- 期間と項目は `ChoiceChip` の折り返しで選ぶ。どちらも単一選択で、読み上げでは選んだ
  状態を伝える
- 一覧は `ListView.builder` を `reverse: true` で置き、今日の行を末尾（下）にして開く。
  見える行だけを作るので、90 行でも作る行は画面に入る分である
- 行は日付と添え書きと 5 つの枠を 1 段に置き、入りきらない大きな文字では枠を次の段へ
  送る。気を付けることの名前は枠の下の段に置く
- 5 つの枠は押せない。今日のページの段のボタンと同じ並びにし、記録した段の枠を塗る。
  段の語は読み上げにだけ出し、枠の上には出さない（行ごとに 5 つの語は並ばない）
- 下端のナビゲーションは、画面の先頭（スクロールの起点）から送ると畳み、戻すと出る。
  `reverse` の一覧では起点が今日の行（下端）なので、古い日へ遡ると畳み、今日へ戻ると
  出る

### 日のページ

- 行を押すと、経過の下に日のページ（`/review/day/:date`）を積む。下端のナビゲーションは
  出さない（TASK0013 の規則）。戻る操作で一覧へ帰る
- 日のページは、今日のページの日の部品（段・気を付けること・メモ）を共有し、ヘッダーは
  戻るボタンと日付にする。◀▶ と設定のボタンは置かない
- 日のページは引数の日を出し、`shownDayProvider` を動かさない。そのため今日のページの
  日の部品を、出す日を受け取る形へ分ける
- 書き換えは今日のページと同じ規則で保存する。一覧は帰ったときに読み直す
- 代わりの案（今日の行き先へ移り、その日を出す）は採らない。戻る操作でアプリが閉じ、
  今日のページの日も動くためである（裁定を求める。未裁定の残課題）

### 色

- 地と部品の色は毎日の記録の画面の役割を使う（テーマは 1 つのまま）。経過は毎日の記録の
  別の見方なので、R1 の「毎日の記録」の地（V3）を経過の画面へ広げる
- 行は地（V3 `#E2E7E3`）へ直に置く。印（塗った枠）と文字は地の文字の色（V4）で、V3 に
  対して 10.27:1。空の枠と区切りの線は輪郭の弱い色（V51）で、V3 に対して 4.50:1
- 足す値の候補と比は、実装の段で見え方記述へ書き、appearance-derive と色の自動テストで
  照らす。比は WCAG の相対輝度の式で測った（2026-10-09）

| 今日 2026-03-01・`plusDays(-1)` | 2026-02-28 |
| 今日 10/4・診察日 9/12 と 9/26 | 前回の診察日は 9/26、期間は 9/26〜10/4 の 9 日 |
| 今日 10/4・診察日 9/26 と 10/4 | 前回の診察日は 9/26（今日を含まない） |
| 今日 10/4・診察日なし | 「前回の診察から」は選べず、期間の既定は 2 週間 |
| 期間 1 週間・今日 10/4 | 添え書きは 10/4 の行の「今日」だけ |
| 9/30 の全体が 3、10/1 に記録なし | 9/30 の行は 3 番目の枠に印、10/1 の行は枠だけで「未記録」 |

## 実装計画

1. ドメインとデータ: `CalendarDay.plusDays`・期間・前回の診察日・一覧の行、ポートの期間の
   読み出しと drift 実装、単体テスト
2. 日の部品の分離: 今日のページの日の部品を、出す日を受け取る形へ分ける（振る舞いは
   変えない。既存のテストで確かめる）
3. 一覧の行: 5 つの枠・印・添え書き・気を付けること・メモの印・区切りの行・読み上げの節、
   大きな文字での折り返し、ウィジェットのテスト
4. 経過の画面: 期間と項目の選択・末尾で開く・今日の移り・読み込みの失敗・
   読み直しの回数、ウィジェットのテスト（最大の文字サイズ・押せる大きさを含む）
5. 日のページ: ルート・戻る操作・帰ったときの読み直し、テスト
6. 見え方記述: 経過の画面の地と一覧の色の値、appearance-derive、色の自動テスト
7. 実機の検証: 見え方・TalkBack・最大の文字サイズ・ナビゲーションの出入り
8. ドキュメント: 機能への反映
9. 自己コードレビュー（CP5）と第三者視点レビュー（CP6）

各ステップの末でコミットし、`scan_diff.py` で規模を測って自己コードレビューを回す。
着手は TASK0014 が `main` に入ってからにする。

## 機能への反映

### 新しい機能（番号は導出のときに採る）

外部仕様(what):
- 下端のナビゲーションの「経過」から、体調の推移の画面を開ける
- 期間（前回の診察から・1 週間・2 週間・4 週間）と項目を選び、1 日 1 行の一覧で推移を
  見られる。各行は今日のページと同じ並びの 5 つの枠に印を置く。記録の無い日は補わない
- 今日の行に「今日」の添え書きがある
- 気を付けることができた日の行に、その名前が出る。メモのある日の行に印が出る
- 期間の中の診察日の前に区切りが入る
- 行を押すと、その日の記録のページが開く。戻ると一覧へ帰る
- 改善・悪化を判定しない

内部設計(how):
- 記録は FEAT0001 の表とポートから期間で読み出す。診察日は診察の記録のポートから読む。
  表は持たない
- 読み出しは provider が持ち、外枠の出し入れによる作り直しでは読み直さない
- 日のページは今日のページの日の部品を共有し、今日のページが出す日を動かさない

自動化できないテスト項目:
- TalkBack での経過
    - 目的: 画面を見ずに、期間と項目を選んで各日の段を聞けるか
    - 期待結果: 選んだ状態が伝わり、各行を「日付、添え書き、項目 段の語、気を付けること、
      メモあり」で読み、記録の無い日を「未記録」、区切りを「診察日」と日付で読む
    - 観察方法: TalkBack を有効にし、期間・項目・一覧の各行の順に移る
- 最大の文字サイズでの経過
    - 目的: OS の文字サイズを最大にしても読めて押せるか
    - 期待結果: 日付・添え書き・枠・気を付けることの名前がはみ出さず、重ならない
    - 観察方法: OS の設定で文字サイズと表示サイズを最大にし、「前回の診察から」と
      4 週間の期間で見る
- 判定に見えないこと
    - 目的: 一覧が、アプリによる改善・悪化の評価に見えないか
    - 期待結果: 枠と印と語の並びが記録の写しとして読め、良し悪しを示す色や記号が無い
    - 観察方法: 記録を増減させた期間を表示し、目視する
