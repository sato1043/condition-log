# 受診先を記録して診察で選ぶ

## 目的

診察を受けた病院・診療科・医師を、診察ごとに打ち込まずに残せるようにする。めったに
変わらない情報なので、受診先として別に記録し、診察ではその一覧から選ぶ。受診先ごとに
診察を見返せるようにする。

あわせて、DB の表と関係を ER 図としてテキストで残す。受診先の表を足すと表どうしの参照が
増えるので、この作業から始める（裁定記録「ER 図」。目的が 2 つになることは、
CONTRIBUTING の「1 ブランチに 1 つの目的」の例外としてユーザーが選んだ）。

作業の途中で、テスト用の端末と TalkBack で使って分かった不具合（体調と診察の行き来・
使わないの知らせ・ダイアログの読み上げ）も、この作業で直す（裁定 2026-10-07。裁定記録
「体調から開く診察の行き先」「使わないの知らせ」「ダイアログの背景の読み上げ」ほか）。

## 目標

- 受診先（病院・診療科・医師）を記録し、直し、使わないにできる別の画面を持つ（裁定
  2026-10-06）（SREQ0014）
- 診察のページで、記録した受診先から 1 つを選べる。選ばなくてもよい（SREQ0014）
- 診察の一覧を受診先で絞り込める。一覧を開いたときの絞り込み（いつもの受診先）を、
  受診先の画面で選んで保存できる（裁定 2026-10-06）（SREQ0014）
- DB の表と関係を ER 図としてテキストで残し、スキーマとの食い違いをテストで見つける
  （裁定 2026-10-06）
- 体調と診察の行き来と、移したこと・ダイアログの読み上げを、使って分かった不具合への
  裁定（2026-10-07）に沿って直す

## 非目標

- 受診先の情報を外部（病院の一覧・地図・電話）から引かない。外部へ送信しない（憲章の
  制約）
- 受診先から、医療上の判断・受診の勧めをしない（憲章の非目標）
- 病院の下に診療科・医師を置く階層を持たない。1 件の受診先が 3 つの名前を持つ（裁定
  2026-10-06）
- 受診先を DB から消さない。使わないにする（裁定 2026-10-06）
- 受診先を並べ替えない。足した順に並べる
- 1 件の診察に 2 つ以上の受診先を持たせない。同じ日の別の診療科は、別の診察として足す
  （TASK0014 の裁定「同じ日の 2 件以上」）
- 診察の一覧の行に受診先を出さない（裁定 2026-10-06）
- 今日のページの診察のボタンが数える診察を、絞り込みで変えない

## 問題

- 下端のナビゲーションの行き先は 3 つ（診察・体調・経過。FEAT0002）である。受診先の
  画面は行き先にせず、診察の行き先の下の画面にする
- 受診先の記録を受け持つ提供要求が無い。SREQ0013 は「覆わない範囲」に受診先の記録を
  挙げる。受診先を選んで見返せることは利用者が知覚する価値なので、新しい提供要求の候補
  である。導出（spec-derive）の段で採番を裁定にかけ、SREQ0013 の「覆わない範囲」を改める
- 表と列を足すので、DB はスキーマ版 3 になる。表の形は配布の後には移行でしか変えられない。
  版 2 は作者の端末に入っており、版 3 を入れた後は版 2 のビルドへ戻せない
- drift は、移行の段と `beforeOpen` がすべて終わった後に版を書く（drift 2.35.0 の
  `engines.dart` で確かめた）。段の後、版を書く前に止まると、次の起動で同じ段が
  もう一度走る。表の作成は `CREATE TABLE IF NOT EXISTS` なので通るが、列の追加は通らない。
  段は、すでに在るものを作らない形で書く
- `make-migrations` は、`migration_test.dart` がすでに在ると書き換えない（drift_dev
  2.35.0 の `make_migrations.dart` で確かめた）。版 2 → 3 の移行のテストは手で書く
- 移行の段は `beforeOpen`（`PRAGMA foreign_keys = ON`）より前に走るので、移行の間は外部
  キーの検査が効いていない。足す列は NULL を既定とするので、どちらでも `ADD COLUMN` で
  足せる
- 受診先は消さないので、診察からの参照は切れない。参照に `ON DELETE` の規則を持たせない。
  名前を直すと、それを選んだ過去の診察の表示も変わる。医師が替わったときは新しく足して
  古いほうを使わないにする、と補足の文で示す
- 受診先の名前は、病歴（要配慮個人情報）を推知させうる。一覧の行には出さないが、絞り
  込みの部品は選んでいる受診先の名前を出す。いつもの受診先を決めると、一覧を開くたびに
  その名前が出る（裁定「一覧の行と絞り込み」の代償）
- 移行の後、既存の診察はどれも受診先を持たない。いつもの受診先を決めると、次に起動した
  ときから既存の診察が一覧に出なくなる。絞り込みの欄に受診先の名前を出し、欄の名前に
  表示している数と全部の数を添え、欄の選択肢の先頭の「すべて」で戻せるようにする（1 回で
  戻すボタンは持たない。裁定記録「一覧の上の部品」「絞り込みの欄の件数」）
- 絞り込んで足した診察は、その受診先を選んだ状態で作る（裁定 2026-10-06）。使っていない
  受診先で絞り込んでいるときも同じである（裁定 2026-10-06）。その帰結として、同じ日の
  問い合わせは絞り込みの中だけを数える。受診先の無い診察と同じ日には、問い合わせ無しで
  2 件目が足される
- 今日のページのボタンは、その日に 2 件以上の診察があるときと、診察の読み込みに失敗した
  ときに、診察の一覧を開く。一覧が別の受診先で絞り込まれていると、その日の診察が見え
  ない。ボタンから一覧を開くときは、どちらの経路でも絞り込みを「すべて」にする
- いつもの受診先は app_settings の 1 行で、値は受診先の id である。外部キーを持たない
  論理参照なので、ER 図のキーの一覧へ書き、TASK0010 の読み込み（id の付け替え）へ渡す
- 同じ日に 2 件以上の診察があり、どちらの欄も空のとき、一覧の行は日付と「まだ書いて
  いません」だけで見分けられない（TASK0014 の CP6 から）。受診先が違えば絞り込みで分け
  られる。同じ受診先なら見分けられないまま残る
- 受診先を選ぶダイアログと、3 つの欄を持つダイアログは、本アプリで初めての形である。
  最大の文字で収まるかを測る
- 受診先の 3 つの欄は、健康情報の欄と同じくキーボードに学習させない
  （`enableIMEPersonalizedLearning: false`）。この指定は Android だけに効く
- TASK0010 の問題は、書き出す表を作業書の番号で挙げており、TASK0014 の診察の表が漏れて
  いる。表の一覧の正本を ER 図にし、TASK0010 からはそれを指す
- 受診先の画面の位置（`/visits/care-providers`）は、診察のページの位置
  （`/visits/:visitId`）と同じ深さに並ぶ。静的な位置を先に並べ、診察のページとして
  解釈されないことをテストで確かめる
- 起動時に DB を開けないとき（移行の失敗を含む）の共通の失敗の画面は無い（TASK0014 の
  残課題）。本作業の移行が失敗した場合も同じ出方になる

- [x] 受診先の表は、各名前が NULL か空白でない文字を持つこと（`trim(x) <> ''`）と、
  3 つの名前のどれかを持つことを CHECK で守る。SQLite の `trim` は半角の空白（U+0020）
  だけを除く（タブも通る）ので、全角の空白だけの名前はドメインの規則が拒む。CHECK を破る
  行を入れると失敗することをテストで確かめる

ER 図:

- [x] `docs/references/database-schema.md` に、表ごとの列（名前・SQL の型・NULL・
  主キー・既定値・参照・制約・意味）を Markdown の表で書く。表どうしの参照を ASCII の
  図で書く。app_settings のキーの一覧（値の形と、値が指す先）を書く
- [x] 照合テストは、`drift_schemas/app_database/` の版を数として比べて最も大きい版を選び、
  それがコードの版（`schemaVersion`）と等しいことを確かめる。その版の `fixed_sql` を
  メモリ上の SQLite で実行し、表の集合・各表の列（名前・型・NOT NULL・主キー・既定値）・
  参照を、ER 図の表と両方向で照らす。読み取りが 0 件なら失敗にする。食い違いはすべて

### ドメイン

- **受診先**（`CareProvider`）: id（数）・名前（`CareProviderNames`）・使うか（`inUse`）
- **受診先の名前**（`CareProviderNames`）: 病院（`hospital`）・診療科（`department`）・
  医師名（`doctor`）。どれも省けるが、少なくとも 1 つを持つ。各名前は名前の規則で整え、
  作るときにこの不変条件を確かめる（満たさなければ `ArgumentError`）
- **受診先の表示名**: ドメインは持っている名前を病院 → 診療科 → 医師名の順に返す。区切りで
  1 つの文にするのは UI で、区切りの文字は ARB に置く
- **診察**（`Visit`）: TASK0014 の形に、受診先の id（`careProviderId`、無ければ null）を
  足す。必須の名前つき引数にし、写しのメソッド（`withToAsk`・`withHeard`）と等価の比べで
  落ちないようにする
- **絞り込み**（`VisitFilter`）: 「すべて」か 1 つの受診先。閉じた集合なので網羅の形で
  分岐する。絞り込みの適用（`VisitFilter.apply`）は区分（`Visit.splitOn`）の前に 1 か所で
  掛ける
- **絞り込みの選択肢**: 「すべて」・使っている受診先・診察が選んでいる使っていない受診先・
  いま絞り込んでいる受診先。ドメインの関数にして単体テストで確かめる
- **いつもの受診先**: 0 か 1 つ。使っていない受診先は、いつもの受診先として働かない

### ポート

```dart
abstract interface class CareProviderRepository {

  Future<void> setCareProviderInUse(int id, {required bool inUse});
  Stream<int?> watchUsualCareProvider();             // 働かなければ null

// VisitRepository へ足すもの

```

- いつもの受診先は読み出しの側だけで守る。`watchUsualCareProvider` は app_settings の行と
  受診先の表の両方の変化を見て、指す受診先が無い・使っていない・値が数でないときは null を
  返す。数でない値と無い id は報告する（`day_start_hour` の先例）。使わないにしても
  app_settings の行は消さないので、元に戻すといつもの受診先も戻る
- 3 つの名前は 1 つの値（`CareProviderNames`）にまとめて渡す。引数の並びの取り違えを型で
  防ぐ

### 表と移行

```
care_providers
  id          INTEGER PRIMARY KEY AUTOINCREMENT
  hospital    TEXT NULL  CHECK (hospital IS NULL OR trim(hospital) <> '')
  department  TEXT NULL  CHECK (department IS NULL OR trim(department) <> '')
  doctor      TEXT NULL  CHECK (doctor IS NULL OR trim(doctor) <> '')
  in_use      INTEGER NOT NULL DEFAULT 1   bool
  updated_at  INTEGER NOT NULL             いまは読まない（daily_logs と同じ）
  CHECK (hospital IS NOT NULL OR department IS NOT NULL OR doctor IS NOT NULL)

visits
  + care_provider_id  INTEGER NULL REFERENCES care_providers (id)   表の末尾

app_settings
  key 'usual_care_provider' → 受診先の id（行が無ければ無し）
```

- 参照に `ON DELETE` を付けない。受診先は消さないので、規則の要る場面が無い。アプリの
  動いている間（`foreign_keys = ON`）に消そうとすると、参照する診察があれば失敗する
- 索引は付けない。受診先は数件、診察は年に数十件の見込みである
- 版 3 の移行は `stepByStep` の `from2To3` で、`transaction` の中で表を作り、列が無ければ
  足す（`PRAGMA table_info` で確かめる）。版を書く前に止まって段が再び走っても通る
- 手順: `schemaVersion` を 3 にする → `dart run build_runner build
  --delete-conflicting-outputs` → `dart run drift_dev make-migrations` → 移行のテストを
  手で足す → ER 図を版 3 へ直す。ARB を変えたら `flutter gen-l10n` を回す（CONTRIBUTING）

### ER 図

- 置き場所は `docs/references/database-schema.md`。表ごとに見出し（表の名前）と、列の表を
  持つ。表どうしの参照は、ASCII の文字だけで描いた図にする（全角の文字を図の中に置か
  ない。桁がずれるため）
- 型は DB のファイルが持つ SQL の型（`INTEGER`・`TEXT`）で書く。drift の型（`bool`・
  `dateTime`）は意味の欄に書く
- 照合テストは書き出しの `fixed_sql`（`CREATE TABLE` の文）を正本として読む。`fixed_sql`
  は CHECK・型・主キー・既定値・参照を SQL の文で持つ（版 2 の書き出しで確かめた）。
  これをメモリ上の SQLite で実行し、`PRAGMA table_info` と `PRAGMA foreign_key_list` の
  結果を ER 図の表と比べる。SQL の文を自前で解析しない
- CHECK は照らさない。ER 図は CHECK を「日付の形」「1〜5」などの意味で書き、式の写しを
  持たない。CHECK を変えるのは移行を伴う変更なので、ER 図を直す手順（CONTRIBUTING）が
  受け持つ

### 状態

- `careProvidersProvider`（一覧）は `StreamNotifier` で、アプリが動いている間保つ
- `usualCareProviderProvider` は、ポートの `watchUsualCareProvider()` を見る
- `visitFilterProvider` は、一覧で選んだ絞り込みを持つ（アプリが動いている間保つ）。値は
  「まだ選んでいない」か `VisitFilter` で、まだ選んでいなければ効く絞り込みはいつもの
  受診先（無ければすべて）になる。起動時の非同期の読み込みを絞り込みの側へ持ち込まない。
  選ぶ前の値はいつもの受診先を見ているので、いつもの受診先が変わればその場で従う
- 今日のページのボタンは、いつもの受診先を読めないとき、絞り込みを選ぶ前へ戻して
  （`followUsual`）一覧を開く。一覧がいつもの受診先の読み込みの失敗を出す。ボタンの
  状態（待つ・足す・開く・一覧を開く・選ぶ前へ戻して一覧を開く）は閉じた集合で、網羅の
  形で分岐する
- 足して開く流れ（`addVisitAndOpen`）は受診先の id を受け取る。一覧は効いている絞り込みの
  受診先を、今日のページはいつもの受診先を渡す
